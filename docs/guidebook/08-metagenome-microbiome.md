# 第 8 章 宏基因组与微生物组

> 这一章是本指南里最长的一章，原因不是工具多，而是**这一步的结论真假主要由统计决定，而不是由软件决定**。
> 工具链（DADA2、Kraken 2、MetaPhlAn、MEGAHIT、MetaBAT2）已经成熟到「照着文档跑就能出结果」的程度；
> 但这些结果几乎总会出现「显著差异」，而其中相当一部分是数据性质制造的假象。
> 8.5 节占了全章一半以上篇幅，如果你只有十分钟，请直接读 8.5.1、8.5.2、8.5.6。

## 8.1 这一层要回答什么问题

微生物组分析的第一个岔路口不是「用哪个软件」，而是**你能回答哪一类问题**。同一个样本，走扩增子路线和走宏基因组路线会得到两套不同分辨率的答案，而且这两套答案的丰度数字不能互相换算。

三类问题的分辨率上限：

| 你想回答 | 需要的最低分辨率 | 能胜任的路线 |
|---|---|---|
| 群落里有哪些类群、各占多少、组间结构是否不同 | 属水平 | 16S/ITS 扩增子 |
| 某个物种（种水平）是否在病例组富集 | 种水平 | 鸟枪法宏基因组（读长级分类） |
| 有没有某个基因、某条通路，是谁在做 | 基因/通路 | 鸟枪法宏基因组（功能谱）+ MAG 路线 |
| 有没有新物种、新基因组，基因组里有什么 | 基因组 | 组装 + 分箱（MAG），受组装与分箱限制 |
| 有没有病毒、噬菌体、可移动元件 | 序列/基因组 | 组装 + 病毒识别，受深度限制 |

### 8.1.1 路线一：16S/ITS 扩增子 vs 鸟枪法宏基因组

这是全章最重要的一个判断，因为它决定了后面所有步骤、成本与结论强度。两条路线**能回答的问题不同**，不是「精度高低」的关系：

**扩增子（16S/ITS）能做什么、不能做什么**

- 只能给出**属水平**为主的分类学组成。16S 高变区片段（例如 V4 约 253 bp）在不同物种间差异太小，可靠到种基本做不到；ITS 对曲霉、青霉、镰刀菌等属内近缘种同样无法可靠区分。
- 受**引物偏好**影响：不同引物对覆盖的类群不同，同一批 DNA 用不同引物会得到不同的「群落」。引物还会漏掉部分类群（如某些古菌、部分门类）。
- 受**16S 拷贝数**影响：不同物种的 16S 拷贝数从 1 到十几个不等，读长比例最多反映「相对扩增信号」，不是细胞数比。
- **没有功能信息**。想谈功能必须用 PICRUSt 之类工具去「推断」，而推断结果不能当作实测结果写进结论。
- 好处是便宜、可扩展到几百上千个样本、单样本成本低、方法学积累最厚。做群落组成与多样性比较时它就是默认选择。

**鸟枪法宏基因组能做什么、代价是什么**

- 能到**种水平**（Kraken 2 + Bracken、MetaPhlAn），在覆盖度足够时可以到**株水平**（菌株水平的 SNP/ANI 分析）。
- 能给出**功能信息**：基因家族与通路（HUMAnN）、抗性基因、可移动元件，以及通过组装分箱得到的新基因组。
- 代价：成本高一个数量级（同样深度贵 5–20 倍）；**低生物量样本灵敏度差**——宿主 DNA 占 99% 以上的组织样本、皮肤拭子、呼吸道样本，微生物读长本来就只有几千到几万条，物种与功能都测不准，这时扩增子的富集优势反而明显。
- 代价还包括：数据量大（几十 GB/样本）、组装分箱算力需求高、分析链更长因而出错点更多。

**判断标准（照这个顺序问自己）**

1. 问题里有没有「功能」「基因」「通路」「新物种」「菌株」这四个词中的任何一个？有 → 宏基因组。
2. 有没有「多样性」「群落结构」「组间组成差异」「哪些菌多／少」？有 → 扩增子通常够用，且能用更低的成本换更大的样本量。**样本量往往比分辨率更决定结论可靠性**（见 8.5.3）。
3. 样本是低生物量类型吗？是 → 优先扩增子；一定要做宏基因组就先把去宿主做干净，并接受灵敏度上限。
4. 预算允许两者都做吗？允许 → 两者都做并**当成两套独立证据**：扩增子给组成与多样性，宏基因组给物种与功能。不要把它们合并成一个丰度矩阵。

> **不要把扩增子的相对丰度和宏基因组的相对丰度当同一个量。** 引物偏好、16S 拷贝数、提取效率、宿主占比在两条路线里的作用方式完全不同，同一个属在两条路线里差两三倍是常态而不是矛盾。跨路线比较只能比较**方向**（升高/降低、有无），不能比较数值。

### 8.1.2 路线二：OTU（97% 聚类）vs ASV

这是扩增子内部的分歧，现在基本已经收敛，但旧流程与旧数据仍然普遍，你必须能解释为什么换。

| | OTU（97% 聚类） | ASV（精确序列变体） |
|---|---|---|
| 定义 | 把相似度 ≥ 97% 的序列聚成一簇，取代表序列 | 数据本身的精确序列，去噪后逐条保留 |
| 可复现性 | 差：换聚类工具、换样本集合、甚至改输入顺序，「OTU_1」都可能对应不同的序列集合 | 好：同一序列在不同研究里就是同一个 ASV |
| 跨研究复用 | 不能 | 可以 |
| 分辨率 | 被 97% 这个人工阈值封顶 | 由数据本身决定，通常更高 |
| 数量含义 | 「簇数」 | 「可区分的序列变体数」 |

**OTU 编号不可跨研究复用**，这一点没有例外。如果你的流程还在输出 `OTU_1`、`OTU_2`，那么这批结果只能在本项目内部自洽，无法与任何已发表数据比较，也无法被他人复用。97% 既不是物种边界，也不是一个稳定的实体。

**ASV 不是物种**，这是换到 ASV 之后最常犯的解读错误。两个具体后果：

- 同一物种的多个 16S 拷贝之间若有差异，会被拆成多个 ASV → **ASV 数系统性高于物种数**，用它当「物种丰富度」会高估。
- 反过来，不同物种也可能共享同一个 ASV（高变区不足以区分）→ ASV 数也可能**低估**某些类群的多样性。

因此论文里必须**同时报告「ASV 数」与「注释到的属/种数」**，涉及「物种数」「丰富度」的结论一律基于注释后的结果，而不是 ASV 数。

**ASV 的代价**要讲清楚，否则会误以为 ASV 只有好处：测序错误如果没有被错误模型识别，就会变成一个假 ASV（低质量数据上尤其明显）；去噪参数（`truncLen`、`maxEE`、`pool`）会实实在在改变 ASV 数量与后续的差异丰度结果。所以参数必须在看了质量分布之后**一次性确定并写进方法**，不能当作调优旋钮反复改到出显著结果。

### 8.1.3 路线三：从「谁在」到「谁在做什么」——分类器的三条路线

读长级物种分类有三条互不相同的路线，它们**不是三个可以互相替代的软件**，而是三种不同的定义方式：

| | Kraken 2（k-mer） | MetaPhlAn（标志基因） | MAG 路线（组装 + 分箱 + GTDB-Tk） |
|---|---|---|---|
| 判据 | k-mer 精确匹配，近缘共享时推到 LCA | 物种特异单拷贝标志基因比对 | 组装出基因组，按标记基因与 ANI 定种 |
| 数字是什么 | 读长分配比例（**不是丰度**） | 标志基因归一化后的相对丰度 | 基因组的覆盖度/相对丰度 |
| 速度 | 最快（分钟级） | 快（几十分钟/样本） | 慢（小时到天，依赖算力） |
| 强弱项 | 灵敏、能给出「像谁」；数字受基因组大小、rRNA 拷贝数、k-mer 独特性影响 | 丰度更接近真实的相对比例、跨样本可比；**只能检出库内物种** | 能得到新物种与完整基因内容；受组装与分箱限制，名录有丰度偏倚 |
| 主要风险 | 数据库版本与内容直接改变结果；默认 `--confidence 0.0` 假阳性最多 | 「没检出」不等于不存在；数据库版本变了丰度也变 | 低丰度物种分不出来、草图基因缺失被误读成「没有这个基因」 |

**三者的结果不可直接比较**，具体表现在：

- Kraken 2 的百分比受**基因组大小**影响：测序深度相同但基因组更大的物种会拿到更多读长。想做丰度必须接 Bracken，或改用 MetaPhlAn。Kraken 2 原始 report 直接当定量用会系统性偏差。
- MetaPhlAn 只统计物种特异的标志基因，做的是**长度归一化**，因此它的物种比例与 Bracken 的物种比例本来就不是同一个量；「某个属在两种方法里差好几倍」是常态。
- MAG 路线的「名录」是**被组装、被分箱出来的基因组集合**，低丰度物种天然缺席。所以「MAG 里有哪些门」不能用来比较不同样本的群落组成——那是读长级分类或扩增子的任务。

**正确的用法是把它们当互补的交叉验证**，而不是挑一个当真理：

1. 用 Kraken 2 + Bracken 做快速、灵敏的物种谱筛查，找可疑信号。
2. 用 MetaPhlAn 复核同一批样本的物种相对丰度（它的绝对数值不同，但**方向**应当大体一致）。
3. 对关键物种，回到 MAG 路线确认基因组是否存在、基因内容是什么。
4. 三者方向不一致时，先查数据库版本与去宿主处理，再考虑生物学解释。

### 8.1.4 路线四：MAG 质量门槛的来历

MAG 不是「一个基因组」，是**从混合数据里拼出来的草图**。因此它的质量必须被显式量化，而量化的门槛有明确的理由：

**完整度 > 90% / 污染度 < 5%（MIMAG 高质量）为什么是这个数**

- **完整度低 → 假阴性。** 低完整度意味着成块的基因系统性缺失，不是随机丢几个。用它做「某基因是否存在」「通路是否完整」「代谢潜力」的比较，会产生大量假阴性：你看到的是「这个 MAG 里没有」，而事实是「这次组装没拼出来」。低于 50% 的 MAG 只适合做「谁在」层面的参考。
- **污染度高 → 凭空造出基因。** 污染意味着混入了其他生物的序列，会制造出基因组里本来不存在的基因，并抬高某些功能（例如把一个质粒的耐药基因算到宿主头上）。因此关键分析不要把污染度放宽到 10% 以上。

**短读长宏基因组几乎检不到 rRNA。** MIMAG 草案的完整定义还要求含 5S/16S/23S rRNA 与足量 tRNA，但 rRNA 操纵子是高拷贝重复区，短读长组装会在那里断掉。**机械套用 MIMAG 的 rRNA 条件会把绝大多数真实 MAG 判为「非高质量」**，掩盖真正的问题。实践上的做法是只把完整度/污染度当门槛，把 rRNA/tRNA 当加分项，并在方法里说明这个取舍。

**污染度 0% 不等于没有污染。** CheckM2 的污染度来自「多个单拷贝标记基因出现多份」这一信号。如果混入的是近缘物种，或者污染量大致相当，拷贝数看起来仍然正常，它就检测不到；整段来自近缘物种的替换同样逃得过。关键结论（新物种、关键基因、通路缺失）应再用 GUNC 或覆盖度均匀性做额外验证。

另外两条硬事实：

- **CheckM1 与 CheckM2 的数值不可混用**，同一 MAG 的完整度能差十几个百分点。方法里必须写明工具与版本。
- **去冗余前后都要报告质量分布。** dRep 按「完整度 − 5×污染度」一类打分选代表，只报去冗余后的分布，读者无法判断最终集合有没有被择优到失真。

### 8.1.5 路线五：病毒组的特殊困难

病毒组不是「细菌组换一个数据库」，它有三条额外的限制：

1. **丰度低、组装难。** 病毒序列丰度通常远低于细菌，很多病毒只能拼出碎片。因此「识别出的病毒数」强烈依赖测序深度与组装质量，**不宜跨项目比较绝对值**。
2. **「病毒物种」没有统一定义。** 细菌有 16S 与单拷贝标记基因做锚，病毒没有。vOTU 完全依赖聚类阈值（95% ANI 只是惯例而非标准），换一个阈值「病毒种类数」就变。
3. **CheckV 的完整度分级决定了哪些序列能做基因组层面分析。** 只有完整（complete）与高质量（high-quality）的序列适合做「病毒基因组」层面的结论（基因内容、宿主范围、生活方式）；中等及以下的碎片只适合做丰度与粗分类。

还有两个高频误读：**前病毒必须单独处理**（溶原病毒整合在宿主基因组里，只做 contig 级识别会系统性漏掉它）；**DNA 宏基因组检不到 RNA 病毒，也无法评估感染性**——检出核酸不等于存在感染性病毒颗粒。

## 8.2 输入、输出与中间文件长什么样

### 8.2.1 输入

| 输入 | 形式 | 关键要求 |
|---|---|---|
| 测序读长 | `*_R1.fastq.gz` / `*_R2.fastq.gz` | 文件名与样本名必须能一一映射；不要在这一步改名 |
| 样本元数据 | TSV（样本 × 变量） | **必须有**：样本名、分组、批次、受试者 id、（低生物量项目）是否空白对照 |
| 空白对照 | 同批处理的采样空白与试剂空白 | 低生物量项目**从导入阶段就要一起保留**，事后补不回来 |
| 参考数据库 | SILVA/Greengenes2、UNITE、Kraken 库、MetaPhlAn index、GTDB、CheckM2 模型 | **版本与构建日期必须记录**，其权重常高于软件版本 |
| 参考基因组/注释 | 宿主基因组、GTDB 参考、rRNA 参考序列 | 去宿主与 rRNA 相关步骤的前提 |

**元数据表是这一步最容易被低估的输入。** 三类列如果在建表时没写，事后无法从数据里恢复：

- `batch`（提取批次 / 建库批次 / 测序 lane）：不同批次的试剂污染谱不同，污染是**批次特异的**，不记录批次就没法在模型里处理它，也没法判断「组间差异」是不是批次差异。
- `subject`（受试者 id）：没有它就无法识别伪重复（8.5.4），也无法用混合效应模型或限制置换。
- `control_type`（样本 / 采样空白 / 试剂空白）：decontam 需要它来区分「环境里的真实微生物」与「试剂污染物」。把采样空白与试剂空白混在一起判定，会把皮肤样本的环境菌判成污染物。

### 8.2.2 扩增子路线的中间文件

```
00_raw/           R1/R2.fastq.gz
01_clean/         *.clean.fq.gz                 # fastp 之后
02_amplicon/
  ├── manifest.tsv                              # sample-id, forward-absolute-filepath, reverse-absolute-filepath
  ├── demux.qza / demux-summary.tsv             # 导入 + 质量/读长数总览
  ├── table.qza                                 # feature-table（ASV × 样本，原始整数计数）
  ├── rep-seqs.qza                              # ASV 代表序列
  ├── denoising-stats.tsv                       # input/filtered/merged/non-chimeric 逐样本统计
  ├── taxonomy.qza / taxonomy.tsv               # 注释结果（含置信度）
  ├── table-no-contam.qza                       # decontam 之后
  ├── core-metrics-results/                     # 多样性
  │   ├── observed_features_vector.qza / shannon_vector.qza / faith_pd_vector.qza
  │   ├── bray_curtis_distance_matrix.qza / unweighted_unifrac_distance_matrix.qza
  │   └── bray_curtis_pcoa_results.qza
  └── phyloseq.rds
09_results/       rarefaction_curve.pdf, alpha_boxplot.pdf, pcoa.pdf, composition_bar.pdf
10_logs/          环境导出、命令、版本清单
```

几个文件的内容要点：

- **`denoising-stats.tsv` 是必读的**，而且要看四个比例的**变化**，不是看 ASV 数。merged 占比骤降 → R1/R2 重叠不足（`truncLen` 太短或扩增子太长）；filtered 占比很低 → `maxEE`/`truncLen` 过严；non-chimeric 掉得多 → 引物没切干净或 PCR 循环数过高。
- **feature-table 是稀疏矩阵**，大量零值是正常的（低丰度类群本来就在多数样本里检不到）。不要用「零多」判断数据质量差；真正的质量问题是抽样深度不足，看 non-chimeric 读长数而不是 ASV 数。
- **距离矩阵与 PCoA 坐标要落盘。** 图上「分得开」不能凭肉眼判断，PERMANOVA 的 R² 与 betadisper 的结果必须来自矩阵本身。

### 8.2.3 宏基因组读长级分类的中间文件

```
02_metagenome/
  ├── kraken2/{sample}.report                 # 层级报告（必须加 --use-names 才可读）
  ├── kraken2/{sample}.kraken                 # 逐读长分配（体积大，可选保留）
  ├── bracken/{sample}.S.bracken              # 重估后的物种丰度
  ├── bracken/{sample}.S.bracken.report
  ├── metaphlan/{sample}_profiled.tsv         # 各层级相对丰度（注意：每个层级内部各自归一）
  └── humann/{sample}_genefamilies.tsv
              {sample}_pathabundance.tsv
              {sample}_pathcoverage.tsv       # 通路完整度：低 coverage 不等于「通路存在」
```

**MetaPhlAn 输出的一个陷阱**：界/门/属/种各层级的相对丰度是**分别在各自层级内归一的**，把不同层级的行混在一起求和或比较是常见错误。

### 8.2.4 MAG 路线的中间文件

```
03_assembly/
  ├── {sample}.contigs.fa                     # MEGAHIT / metaSPAdes 输出
  ├── {sample}.sorted.bam                     # 读长回贴（分箱必需）
  └── {sample}.depth.txt                      # jgi_summarize_bam_contig_depths 生成
04_binning/
  ├── metabat2/bins/*.fa                      # 候选 bin
  ├── das_tool/bins/*.fa                      # 合并后
  ├── drep/dereplicated_genomes/*.fa          # 去冗余代表
  └── checkm2/quality_report.tsv              # Completeness / Contamination / Genome_Size
05_taxonomy/gtdbtk/gtdbtk.bac120.summary.tsv  # 分类与 ANI（相对最近参考，不是成对 ANI）
```

**这里有一个必须在文件层面体现的纪律：分箱前按长度过滤。** 短 contig 的四核苷酸频率估计噪声大，是分箱的主要污染源。常见阈值是 ≥ 1000–2500 bp（MetaBAT2 默认 `-m 2500`，MaxBin2 默认 `--min_contig_length 1000`），两个工具要取一致的阈值，否则结果不可比。建议在分箱前过滤而不是在组装时硬删，这样原始 contig 还能用于追查。

**另一个纪律：`bins/*.fa` 不能直接当丰度用。** dRep 去冗余后的代表只是一个**序列实体**；「该物种在某样本里的丰度」必须回到每个样本单独定量（读长回贴 / 覆盖度），并用聚类成员表把成员样本的丰度归并到代表上。把代表序列的存在当成丰度是常见错误。

### 8.2.5 病毒组路线的中间文件

```
02_virome/
  ├── genomad/{sample}_virus_summary.tsv      # 病毒/质粒判定 + 宿主预测（推断而非观测）
  ├── genomad/{sample}_provirus.tsv           # 前病毒区与边界
  ├── checkv/{sample}_quality_summary.tsv     # complete / high / medium / low / not-determined
  ├── votu_clusters.tsv                       # 95% ANI 聚类（阈值必须写进方法）
  └── abundance/votu_abundance.tsv            # 覆盖度（而非读长计数）
```

病毒定量必须**比对回同一套 contig 集合**，并且要注意多重比对（病毒序列与宿主或其它病毒有同源区）如何分配读长。用读长计数比较不同病毒是不可比的：病毒基因组长度差异大（几 kb 到几百 kb），应使用覆盖度并同时报告它作为可信度。

### 8.2.6 每一步的校验点：怎么知道中间文件是对的

「跑完了」不等于「跑对了」。下面这些检查每一项都只需几秒，但能拦住绝大多数会让结论作废的问题。**把它们写进流程，而不是靠人记得查。**

| 步骤 | 要看的量 | 合理区间 / 异常信号 |
|---|---|---|
| 导入 | 每样本读长数 | 同批样本之间不应差一个数量级。差一个数量级 → demultiplex 或 index 问题，**是数据错误不是离群值** |
| 去噪 | filtered / merged / non-chimeric 三个比例 | merged 骤降 → 重叠不足；filtered 很低 → `maxEE`/`truncLen` 过严；non-chimeric 掉得多 → 引物没切干净或 PCR 循环数过高 |
| 去噪 | 非嵌合读长数（不是 ASV 数） | 抽样深度是否足够的唯一依据；ASV 数量不反映深度 |
| 注释 | unidentified / uncultured 占比 | 环境样本 20%–40% 拿不到属名是常态。**为降低这个比例而放宽阈值是错的** |
| decontam | 删除的 ASV 数与读长占比 | 必须报告；读长占比很高时说明污染严重，应先查提取/建库流程 |
| 多样性 | 每样本读长数分布 + 稀释曲线 | 未达平台期的样本，其 richness 不可比较 |
| beta 多样性 | PERMANOVA 的 R² 与 p、betadisper 的 p | 只报 p 是不够的；离散度显著不同时先查样本质量 |
| Kraken 2 | unclassified 比例 | 高不一定是数据差（缺参考的环境样本、病毒多）；**极低也要警惕**（库过度膨胀导致读长被强行分配） |
| Bracken | 高丰度物种的同属代表基因组数 | 只有 1–2 个基因组时高度怀疑**幽灵物种** |
| MetaPhlAn | 各层级相对丰度是否各自归一到 100% | 把不同层级的行混在一起求和是常见错误 |
| HUMAnN | unmapped 比例 | 反映参考库覆盖度不足（新物种、病毒、非模式类群），**不是质控指标** |
| 组装 | 回贴率、未比中比例 | 这才是宏基因组组装的质量指标；contig N50 不是 |
| 分箱 | bin 数量 + CheckM2 完整度/污染度分布 + 基因组大小分布 | **不能用 bin 数量判断好坏**；大量「完整度还行」的小 bin 说明同一个基因组被切碎 |
| 定量 | 同一 MAG 集合是否贯穿所有样本 | 换过参考集合就必须全部重新定量 |
| 病毒 | CheckV 质量等级分布 + geNomad 判定分数阈值 | 只有 complete / high-quality 能做基因组层面结论 |

**一个通用原则**：任何一步的产物落盘后，除了检查「文件存在且非空」，还要检查**它包含的样本数与特征数**。0 字节文件会被下游当成空数据；而「只有 3 列却有 30 个样本」这种问题不会报错，只会在你发现分组少了一半样本时才浮现。

## 8.3 工具拼装思路（含选择决策树）

### 8.3.1 第一层决策：走哪条路线

```
问题里有没有「功能 / 基因 / 通路 / 新物种 / 菌株」？
├── 有 ──→ 鸟枪法宏基因组
│          ├── 只要物种谱与功能谱 ──→ 读长级路线（Kraken 2 + Bracken / MetaPhlAn + HUMAnN）
│          └── 要新基因组、要基因内容 ──→ 加组装 + 分箱（MAG）
└── 没有，只问组成 / 多样性 / 群落结构
           ├── 样本是低生物量（皮肤、呼吸道、组织、水）？──→ 扩增子（16S 或 ITS）
           └── 常规样本 ──→ 扩增子；样本量能做大就做大，样本量比分辨率更值钱
```

再补两个约束条件的判断：

- **要不要做 MAG？** 判据不是「想不想」，而是**样本数与覆盖度够不够**。分箱依赖多个样本的覆盖度差异，单样本分箱效果很差；样本数越多（尤其覆盖度差异大的组合）越好。土壤这类高多样性群落的 MAG 常常拼不出可用的完整度，这时正确的做法是承认上限，退回到读长级物种谱。
- **要不要做病毒组？** 只有当测序深度足够、且研究问题本身是病毒时才做。病毒丰度低，深度不足时「识别出的病毒数」几乎完全由深度决定，跨项目比较没有意义。

### 8.3.2 扩增子：从读长到群落差异

对应面板预设 `preset-16s-diversity`（9 个节点）。下图的箭头与预设里的连线**逐条对应**：

```
amplicon_qiime2_import → amplicon_dada2 → amplicon_taxonomy_assign ─┬→ amplicon_decontam → amplicon_qiime2_diversity ─┬→ viz_rarefaction_curve
                                                                   │                                                  └→ viz_alpha_beta
                                                                   └→ amplicon_phyloseq ───────────────────────────────→ viz_composition_bar
```

顺序上有两个**不能调换**的位置：

1. **引物切除在导入阶段做**（q2-cutadapt），不能拖到去噪之后。残留引物会成为所有 ASV 共有的前缀，让去噪把引物差异当真实变异，也让嵌合体更容易产生。
2. **decontam 在去噪之后、任何组间比较之前做。** 同一批试剂污染在不同样本里的比例不同，会让组成看起来「有生物学差异」；等差异分析出结果后再回头怀疑污染，已经太晚。

**DADA2 还是 Deblur？**

```
数据是 ITS 吗？
├── 是 ──→ 只能 DADA2（ITS 长度变异大，无法截断到统一长度；Deblur 会丢掉大部分真菌）
└── 不是 ──→ 两者都可以，但有三个硬差别：
      ├── Deblur **不做嵌合体去除**，必须自己补一步；不补则 ASV 数与「新类群」明显虚高，
      │   而且这些嵌合序列集中在低丰度端，正好污染稀有生物圈的分析
      ├── Deblur 需要统一截断长度（16S 常用 150），截短会降分类分辨率、截长会把低质量尾端带进来
      └── 两者的 ASV 集合**不可互换、不可跨方法合并**；中途换方法必须把全部样本重跑，
          否则样本间差异里混着方法差异，而这种差异恰好与批次相关时最难发现
```

**注释数据库怎么选？** 只有一个原则：**训练区域必须与扩增区匹配**。用 V4 训练的分类器去注释 V3–V4 的 ASV，流程能跑完、也会给出名字，但准确度明显下降，而且这种错误从输出上看不出来。SILVA 与 Greengenes2 的分类层级与命名差异很大，**换数据库 = 换答案**；跨研究比较前先统一体系，或退到门/纲这样的高层级。

### 8.3.3 宏基因组读长级：物种谱与功能谱

对应面板预设 `preset-metagenome-species`（9 个节点）。注意**这个预设里有两条并行的证据链，而不是「先粗后细」**：

```
qc_fastp ─┬→ meta_kraken2 → meta_bracken ─────────────→ py_pandas_io ─┬→ viz_composition_bar
          │                                                            └→ py_scipy_stats → viz_volcano_ma
          └→ meta_metaphlan → meta_humann
```

`meta_metaphlan` / `meta_humann` 这一支在预设里是**终点**：HUMAnN 的功能谱没有连线接到下游的 `py_pandas_io`。这符合它的定位（功能谱的输出形式与物种表不同，需要自己决定如何汇总与统计），但也意味着**预设不会替你处理功能数据**——要用功能谱做统计，你得自己把 `*_pathabundance.tsv` 接进去，并按 8.5.1 的组成性要求处理。

两条支路的性质不要混淆：

- **上面一条（Kraken 2 → Bracken）**：Kraken 2 给逐读长分配，Bracken 把它重估为物种丰度。中间这一步不能省——**直接拿 Kraken 的 report 做定量会系统性偏差**。
- **下面一条（MetaPhlAn → HUMAnN）**：MetaPhlAn 给标志基因物种谱，HUMAnN 给基因家族与通路。HUMAnN 既可以吃读长，也可以吃 MetaPhlAn 的物种谱，但**给物种谱时功能是「推断」出来的**，不是在该样本读长上实测到的。

拼装时的四个接口约定：

1. **Kraken 2 的 `-k` 在建库时固定**，运行时改不了；换库必须重建 Bracken 索引（`bracken-build -k` 必须与 Kraken 库一致）。
2. **Bracken 的 `-r` 必须与实际读长一致**（100 bp 数据写 150 会系统性偏移）。
3. **HUMAnN 的归一化单位必须全分析统一**（`relab` 相对丰度 vs `cpm` 长度深度校正），两个量纲混在一张热图或一个检验里，结论没有意义。
4. **去宿主必须彻底。** 去宿主不彻底会让宿主读长被分到近缘微生物上，产生**稳定的**假阳性物种——这种假阳性在结果里看起来非常像真实信号。

### 8.3.4 MAG 路线：组装 → 分箱 → 质量 → 分类

对应面板预设 `preset-mag-binning`（9 个节点）：

```
qc_fastp → qc_remove_host → meta_megahit ─┬→ meta_assembly_qc
                                          └→ meta_binning_metabat → meta_bin_refine
                                                                 → asmqc_checkm2 → meta_mag_taxonomy → viz_tree_plot
```

**四个必须自己动手补的环节**（面板不会替你判断，预设也不会自动跑）：

1. **回贴生成覆盖度。** 「只组装不回贴 = 没有覆盖度」。分箱需要同时使用序列组成与多样本覆盖度；缺了覆盖度，分箱基本退化为按四核苷酸频率聚类，质量明显下降，而且这种下降**在结果里看不出来**（bin 仍然是「正常」的 fasta）。
2. **分箱前按长度过滤 contig**（1000–2500 bp）。
3. **多工具 + 合并 + 去冗余。** 单个工具的输出不能当最终 MAG 集：MetaBAT2 偏稳、MaxBin2 偏碎、SemiBin 偏灵敏。常规做法是 `meta_binning_metabat` 多工具并行 + `meta_bin_refine`（DAS Tool 合并、dRep 去冗余）+ `asmqc_checkm2` 评估。
4. **去冗余前先做质量过滤。** 低完整度的碎片 bin 会参与 ANI 聚类（重叠区不足时 ANI 估计不稳），把高质量 MAG 的聚类边界带偏，还可能被选成某些簇的代表。

**MEGAHIT 还是 metaSPAdes？**

| | MEGAHIT | metaSPAdes |
|---|---|---|
| 内存 | 低（可跑在普通服务器上） | 高（几十到上百 GB，常见 OOM 失败） |
| 速度 | 快 | 慢 |
| 适用 | 常规宏基因组、样本多、算力有限 | 复杂菌株群落、需要更高精度时 |
| 预设 | `--presets meta-large` 针对高复杂度群落（土壤、水体） | `--meta` 是必选项，用 `--isolate` 会严重低估复杂度 |

**不要在同一项目里混用两者的结果。** 两者 contig 命名、长度过滤阈值、图处理策略都不同，混合后「contig 数」「N50」这类比较失去意义，分箱的覆盖度特征也会不一致。

**co-assembly 还是单样本组装？** 优先单样本组装再用 dRep 去冗余。co-assembly 会造成**菌株塌缩与嵌合**：不同样本里同一物种的不同菌株会被拼成一个「平均基因组」，掩盖菌株差异，还可能把不同菌株的基因拼到同一条 contig 上。除非样本群落高度相似，不要 co-assembly。

**关于 contig N50：它不是宏基因组组装的质量指标。** N50 主要由群落复杂度决定（土壤可能只有几 kb，肠道可到几十 kb），跨样本比较毫无意义。真正要看的指标是**回贴率、未比中比例，以及最终 MAG 的完整度/污染度**。

### 8.3.5 真菌 ITS：与 16S 共享统计、不共享参数

对应面板预设 `preset-its-fungal`（6 个节点）：

```
amplicon_qiime2_import → amplicon_dada2 → amplicon_its_fungal → amplicon_qiime2_diversity
                                                             ↘ viz_alpha_beta / viz_composition_bar
```

三个 ITS 特有的判断：

- **不能照搬 16S 的 `truncLen`。** ITS 长度变异极大，固定截断会丢一大部分真菌类群，而且丢的是**系统性的**（长 ITS 的类群先消失），会让组成结果出现假的偏差。ITS 场景常把 `truncQ` 设为 0 并完全依赖 `maxEE`。
- **`pool` 用 pseudo。** ITS 上尤其关键：长度不一致会让「按样本独立学习错误率」失效，`pool=FALSE` 会明显漏检真实 ASV；`pool=TRUE` 又会放大污染。
- **必须先做 ITS 区提取**（ITSx / ITSxpress）再注释。不提取就让两侧保守的 SSU/LSU 主导比对结果，不同物种因为共享保守区而得到过于相似的注释——看起来「注释得很好」，其实分辨力被抹掉了。

真菌特有的一条纪律：**`UNITE` 的 SH 编号不是物种名**。SH（species hypothesis）是参考序列簇的标识，把它当物种写进结果表会误导读者。正确做法是报告最接近的参考序列、相似度与层级。ITS 的可靠上限通常是属，写种名需要第二标记（EF1α、β-tubulin 等）。

植物相关样本（根际、叶际、内生）还要多做一步：**ITS 引物会大量扩增宿主植物**，必须先把宿主序列识别并去除，否则「真菌多样性」里混着植物 ITS，宿主参考序列的版本也要记录。

### 8.3.6 病毒组：识别 → 质量 → 去冗余 → 定量

对应面板预设 `preset-virome`（8 个节点）：

```
qc_fastp → meta_megahit → meta_virome（geNomad 识别 + 宿主预测）
                        ↘ phage_checkv（完整度分级、前病毒切分）
                                  → meta_bin_refine（vOTU 去冗余）→ meta_coverm → viz_composition_bar
```

四个拼装要点：

- **前病毒必须单独处理**，并在方法里说明是否纳入。整合在宿主基因组里的前病毒会被当成长度异常的宿主 contig，只做 contig 级识别会系统性漏掉溶原病毒。
- **geNomad 的判定里会混入质粒与可移动元件。** 它们与病毒在生物学上不同（复制机制、宿主范围、生态含义都不同），应分开处理并分别报告。
- **CheckV 的完整度分级决定下游能做什么**：complete / high-quality 才能做基因组层面分析，其余只做丰度趋势。
- **vOTU 阈值必须写进方法。** 95% ANI 是惯例不是标准；换阈值「病毒种类数」直接变。

**VLP 富集数据与宏基因组数据不可直接比较。** 前者去掉了宿主与大部分游离 DNA（且不同实验的富集效率不同），后者包含前病毒。把两类样本放进同一个丰度矩阵里分析是方法学错误。

### 8.3.7 下游统计怎么接（这是全章的枢纽）

面板预设 `preset-metagenome-species` 把 `py_scipy_stats` 直接接在丰度表后面，但它自带一条明确警告：**不要用常规检验直接比较相对丰度**（组成性数据会产生大量假阳性），应使用 CLR/ILR 变换或 ANCOM-BC、ALDEx2。那里的普通检验只适合做探索性筛查。

正确接法：

```
丰度表（原始计数）
  ├── 多样性比较 ──→ 统一深度 ──→ amplicon_qiime2_diversity / r_vegan_diversity
  │                                     └── PERMANOVA + betadisper 一起报
  ├── 组成性感知的差异丰度 ──→ amplicon_phyloseq（ANCOM-BC / ALDEx2）
  ├── CLR 变换后再做常规检验 ──→ py_scipy_stats（multipletests 用 'fdr_bh'）
  └── DESeq2 路线 ──→ 仅在明确讨论并检验了归一化假设时使用（见 8.5.1）
```

不要把抽平后的表送进计数模型，也不要把 CLR 变换后的值送进 DESeq2。不同的统计方法对应不同的输入形式，混用不会报错，只会给出没有意义的数字。

### 8.3.8 拼装骨架：面板导出的脚本长什么样、要补什么

面板可以把画布导出成 Bash 或 Python 脚本，但它导出的是**结构骨架 + 参数起点**，不是可直接投产的脚本。下面这条扩增子骨架说明了「骨架」与「能跑」之间差什么——每一处 `# ←` 都是必须你自己补的判断：

```bash
#!/usr/bin/env bash
set -euo pipefail
# 版本与数据库记录：不写这些，结果不可复现
mkdir -p 10_logs
{ uname -a; conda list; qiime info; } > 10_logs/env.txt 2>&1

# 1) 导入（含引物切除）
# ← manifest 必须用绝对路径，表头拼写必须完全一致
qiime tools import \
  --type 'SampleData[PairedEndSequencesWithQuality]' \
  --input-path manifest.tsv --output-path demux.qza \
  --input-format PairedEndFastqManifestPhred33V2
qiime demux summarize --i-data demux.qza --o-visualization demux.qzv
# ← 打开 demux.qzv 看长度分布与每样本读长数，再决定 truncLen。
#    这一步不能跳：不看质量分布就定 truncLen 是最常见的错误来源。

# 2) 去噪（DADA2）
qiime cutadapt trim-paired --i-demultiplexed-sequences demux.qza \
  --p-front-f GTGCCAGCMGCCGCGGTAA --p-front-r GGACTACHVGGGTWTCTAAT \
  --p-discard-untrimmed --o-trimmed-sequences demux-trimmed.qza
```

### 8.3.9 参数敏感性分析：怎么证明结论不是调出来的

对本章这些「改了就改变结论」的参数，正确的做法不是「选一个最好的」，而是**证明结论对这些选择不敏感**：

1. **固定主分析**：按事先定好的参数跑一遍，作为主结果。
2. **扰动关键参数**：例如抽平深度取 5000 / 10000 / 20000，去噪 `pool` 取 `pseudo` 与 `TRUE`，decontam `threshold` 取 0.1 / 0.2 / 0.5，dRep 的 `-sa` 取 0.90 / 0.95。
3. **比较结论层面的一致性**，而不是比较数值：显著条目的**重叠率**、效应量的**方向是否一致**、关键结论是否仍成立。
4. **把敏感性结果放进补充材料**。审稿人真正关心的不是「你选了哪个参数」，而是「换一个参数结论会不会变」。
5. **如果结论对某个参数高度敏感，就在正文里说出来。** 这比藏起来被发现要好得多，而且往往正是最有信息量的发现——它说明这部分数据本身不足以支撑强结论。

## 8.4 关键参数取舍

参数的判断原则只有一条：**这个参数改变的是「计算精度」还是「结论本身」？** 前者可以随手设，后者必须一次定好、写进方法、并做敏感性分析。

### 8.4.1 改了就改变结论的参数（必须记录）

**扩增子**

| 参数 | 建议起点 | 改了会怎样 |
|---|---|---|
| `--p-sampling-depth`（抽平深度） | 由 alpha 稀释曲线与每样本读长数分布共同决定 | 取太低丢掉大部分样本，取太高只剩少数样本；**没有默认值，必须自己定** |
| `truncLen`（DADA2） | 按质量分布定，不照抄别人的数 | 太长保留低质量尾端制造假 ASV；太短 R1/R2 重叠不足无法合并 |
| `maxEE` | 2 | 低质量数据上比固定质量阈值更稳健；调严会显著减少保留读长 |
| `pool` | `FALSE`（常规）/ `pseudo`（低生物量） | `TRUE` 会把空白对照里的污染物与 index hopping 固化成「每个样本都有的真实 ASV」 |
| `--p-confidence`（注释） | 0.7 | 提高会让更多 ASV 停在属/科但减少错误种名；降低是过度解读的常见来源 |
| 距离指标 | Bray-Curtis / 加权 UniFrac | 加权与 Bray-Curtis 对丰度敏感，unweighted UniFrac 只看有无、对稀有类群极敏感；**指标选择会改变结论** |
| 用于 Faith's PD / UniFrac 的树 | — | 换建树工具、换参考树、忘记定根都会改变数值；短读长 ASV 自建树可能不可靠，改用 SEPP 插入参考树并记录参考树版本 |

**宏基因组读长级**

| 参数 | 建议起点 | 改了会怎样 |
|---|---|---|
| Kraken 2 `--db` | — | **换库 = 换答案**。标准库、plusPF（含真核与病毒）、自定义库结果差异很大；必须记录库类型与构建日期 |
| Kraken 2 `--confidence` | 0.0（默认，最灵敏） | 0.1–0.5 是常用折中；调高同时抬高 unclassified |
| Kraken 2 `--minimum-hit-groups` | 2 | 这是控制假阳性的实用参数；降到 1 会明显增加误分类 |
| Bracken `-r` | 必须等于实际读长 | 与真实读长不符会让**所有**丰度系统性偏移 |
| Bracken `-l` | `S` | 数据库种级基因组不全时会出现幽灵物种；`G`（属）通常更稳 |
| Bracken `-t` | 10 | 调高过滤掉低丰度物种，让结果更干净但更不完整 |
| MetaPhlAn `--index` | 随安装版本 | 不同版本的物种集合与命名会变，跨版本结果不可直接比较 |
| HUMAnN `--units` | `cpm` 或 `relab`，**同一分析内统一** | 两者量纲不同；混在一张图或一个检验里结论没有意义 |
| decontam `threshold` | 0.1 | 文献里 0.1–0.5 都有人用；调高删得更多（也伤真实低丰度类群）；必须在方法里写明并做敏感性分析 |

**组装、分箱与 MAG**

| 参数 | 建议起点 | 改了会怎样 |
|---|---|---|
| `--min-contig-len`（过滤） | 1000–2500 bp | 短 contig 是分箱的主要污染源；阈值必须写进方法 |
| MetaBAT2 `-m` | 2500 | 分箱后再过滤已经晚了：短 contig 会被分错并污染 bin |
| MetaBAT2 `-a` | 多样本覆盖度文件（必填） | 单样本覆盖度会让低丰度物种分箱质量明显变差 |
| dRep `-comp / -con` | 75/10（默认）；关键分析收紧到 90/5 | 门槛必须与质量评估模块的报告一致 |
| dRep `-pa / -sa` | 0.90 / 0.95 | **90% 与 95% ANI 给出完全不同的「物种数」**；用 90% 会把近缘 MAG 合成一个代表 |
| GTDB-Tk 参考数据版本 | 随安装（如 GTDB R2xx） | 换版本会让部分 MAG 的分类路径与 ANI 值改变，甚至名字被重新分配 |

| CheckV 完整度门槛 | 只用 complete / high-quality 做基因组层面结论 | 其余碎片只适合做丰度与分类 |
| vOTU 去冗余阈值 | 0.95 | 95% 是惯例而非标准；阈值变化直接改变「病毒多样性」的数字 |

### 8.4.2 只影响速度与内存的参数

这些可以按机器条件调整，不影响结果，但**规划不当会让长任务在中途失败**：

- Kraken 2 的内存规划要在跑之前完成：标准库需要数十 GB 内存，plusPF 更大。跑到一半 OOM 会浪费大量时间；内存不足时改用 `--memory-mapping`（依赖磁盘随机读，SSD 上才实用）或裁剪自定义库。
- metaSPAdes 的内存上限设得超过物理内存不会让它变快，只会在某个 k 轮被 OOM killer 杀掉；**日志末尾可能没有明确报错**，只留下不完整的输出目录。跑了几个小时才发现失败很常见，务必按内存（而不是核数）规划并发并检查退出状态。
- HUMAnN 读长模式单样本数小时、数十 GB 内存是常态，批量提交前先用一个样本评估。
- `amplicon_qiime2_import` 的 `--p-cores` 在批量几十上百样本时不设会非常慢。

### 8.4.3 三个「不能当调优旋钮」的参数

这三类参数有一个共同特征：**调整它们会让结果「变好看」，而变好看的原因往往是数据被删掉了**。

1. **decontam 的 `threshold`**。提高阈值删掉更多序列，往往会让组间差异变得「更干净」——那是删数据删出来的，不是发现。
2. **注释的置信度门槛**。降低它会报出更多种名，让「注释率」看起来更漂亮，代价是错误种名。
3. **去噪参数（`truncLen` / `maxEE` / `pool`）**。反复调参直到显著，等于把 p 值选择做进了预处理。正确顺序是：**看质量分布 → 一次性确定参数 → 写进方法 → 跑到底**。

## 8.5 常见坑

本节的结构统一为 **症状 → 机制 → 怎么办**。8.5.1–8.5.6 是六个统计陷阱，它们比任何参数都更能决定结论真假；8.5.7–8.5.8 是生物学解读与流程文件层面的坑；8.5.9 用一个完整案例把它们串起来，8.5.10 是可以直接拿去用的自检清单。

### 8.5.1 组成性（compositional）数据：这是本章最重要的一节

**症状**

差异丰度分析跑完，得到一张长长的显著物种表：一半「显著升高」，一半「显著降低」。换一个统计方法再跑一遍，显著清单重叠不到一半。审稿人问「这个菌升高是不是因为别的菌减少了」，你答不上来。

**机制**

测序仪给出的不是绝对量，而是**相对比例**。任何一次归一化（除以总读长、转成百分比）都会让所有特征的和恒等于 1（或 100%）。这是一个**约束**，不是数据的性质：

> 只要总和固定，一个特征上升，**必然**伴随其它特征（至少一个）下降。

这意味着两件事，而它们是所有假阳性的来源：

1. **特征之间被人为地变成负相关。** 即使两个物种在真实世界里完全独立、绝对量都不变，只要其中一个在测序中多占了一点比例，另一个的比例就会机械地下降。常规检验（t 检验、Mann-Whitney、Kruskal-Wallis）的零假设是「两组独立、方差结构正常」，而组成性数据把这个前提破坏了——它们检验的零分布根本不对应「没有生物学差异」这一情形。
2. **「显著升高」与「显著降低」的条目往往是同一现象的两种表现。** 一个高丰度类群变化，会在整个特征集上产生成片的、方向相反的假阳性。所以一张「有 30 个菌升高、25 个菌降低」的表，可能真实情况只有 1–2 个类群真的变了。

还有第三个放大因素：**微生物组数据同时是稀疏的（大量零）和零膨胀的**。低丰度类群在多数样本里为 0，一旦在少数样本里出现几条第长，比例就会大幅波动。这类特征在常规检验里最容易达到显著。

**一个数值示例，把这件事说透**

假设一个极简的群落，只有 3 个物种，两组各 5 个样本。真实情况是**三个物种的绝对量完全相同**，唯一的差别是：B 组的样本在测序前多了一段「其它来源」的读长（例如宿主 DNA 残留或试剂污染），把 A 组的 1000 条序列挤成了 800 条。

| | 物种 X 绝对量 | 物种 Y 绝对量 | 物种 Z 绝对量 | 其它 | 总读长 |
|---|---|---|---|---|---|
| A 组 | 400 | 300 | 300 | 0 | 1000 |
| B 组（含污染） | 320 | 240 | 240 | 200 | 1000 |

测序只给你相对比例，于是：

| | X | Y | Z | 其它 |
|---|---|---|---|---|
| A 组 | 40.0% | 30.0% | 30.0% | 0% |
| B 组 | 32.0% | 24.0% | 24.0% | 20% |

现在对 X 做 t 检验：A 组每个样本的 X 占比大约在 40% 附近，B 组在 32% 附近，差异稳定、方差不大。**X、Y、Z 三个物种全部会「显著降低」——而它们的绝对量一个都没变，只是总池子里多了一样东西。**

这就是组成性假阳性的最小模型。现实数据里还有第二层放大：如果这个「其它」本身也是一个被测到的类群（比如某个试剂污染物属），那么它会在同一批检验里「显著升高」，看起来像一个真实的生物学发现。

**结论**：在相对丰度上做常规检验，你检验的不是「这个类群变多变少」，而是「这个类群的**份额**变没变」。份额的变化可以由它自己、也可以由别人引起，而检验本身无法区分这两者。

**怎么办**

这是本章唯一给出「照做就行」的清单：

1. **换检验方法，而不是换软件界面。** 三条被广泛接受的路线：
   - **对数比变换 + 常规统计**：先做 CLR（centered log-ratio）或 ILR（isometric log-ratio）变换，把组成性数据映射到无约束的实数空间，再对变换后的值做常规检验。这是最通用的做法。
   - **ANCOM-BC**：显式估计并校正样本的**采样分数**偏倚，同时处理结构零，直接给出各组间的差异丰度与置信区间。它输出的效应量就是「组间丰度比的对数」量级，可直接解释。
   - **ALDEx2**：CLR 变换 + Monte Carlo 抽样（`mc.samples`，默认 128）来刻画组成性带来的不确定性，对零值用 Dirichlet 抽样处理。

   三者的零假设不同，因此**显著清单不会完全一致**——这是正常的，不是 bug。做法是把**三种方法一致的条目**当结论，不一致的当待验证信号。

2. **绝不在相对丰度上直接跑 t 检验 / Mann-Whitney / Kruskal-Wallis。** 面板预设 `preset-metagenome-species` 里的 `py_scipy_stats` 明确写了这条：那里的普通检验只适合做**探索性筛查**，不能作为结论。如果你只有 SciPy，那么至少先 CLR 变换再用，并且记住 CLR 的零值处理会引入额外假设。

3. **多重校正必须对全部检验一次性做。** 分批校正（例如按门分别校正）会让每一批都有人为的显著结果。用 `py_scipy_stats` 时注意 `multipletests` 的默认方法是 `'hs'`（Holm-Sidak，控制 FWER），在几千次比较时过严，几乎不会有显著结果；绝大多数生信场景应该用 `'fdr_bh'`。

4. **报告效应量，不要只报 p 值。** 用 p 值单独排序「重要菌」是错的。效应量（log2 倍数变化、CLR 差）与检出率一起看，才能区分「差异小但样本一致」与「差异大但只在一个样本里」。

5. **显式处理零值，并做敏感性分析。** CLR 对零值没有定义，必须选择伪计数或零值替换方法，不同处理会让效应量不可比。「加伪计数 + CLR」会掩盖真正的结构零；「直接删掉零多的特征」又会改变组成性基准（删掉一个特征，其余特征的比例全部重新归一）。两种做法都行，但必须显式选择、记录，并检验结论是否稳健。

6. **预筛选会让 p 值失去标称性质。** 对已经筛过的数据再做检验（例如「只对在至少一半样本中检出的物种做差异检验」），p 值不再具有标称性质。这类预筛选必须写进方法。

**为什么 DESeq2 在这类数据上有风险**

DESeq2 在微生物组论文里出现得非常多，但它不是为这类数据设计的，三个假设会在扩增子/物种表上破裂：

1. **median-of-ratios 归一化假设「大多数特征不差异表达」。** 扩增子表里有大量结构零与低丰度特征，很多特征在多数样本里根本检不到，「大多数特征不变」这个前提很难成立。微生物组的差异往往是**成片**的（一个门整体变化），而不是少数基因的孤立变化，这恰好是最坏的情形。
2. **离散度（dispersion）估计的分布假设不匹配。** DESeq2 的负二项模型是为 RNA-seq 的计数分布设计的；扩增子数据的方差-均值关系不同（零膨胀、过高比例的零），离散度估计会偏，而离散度是所有 p 值的基础。结果通常是**偏激进**（假阳性偏多）。
3. **抽平之后再跑 DESeq2 是错的。** 这类模型需要**原始整数计数**；抽平会改变计数的方差结构，等于在模型假设之外又加了一层加工。抽平只适用于多样性比较，不适用于计数模型。

用 DESeq2 也不是绝对禁止，但必须做三件事：**明确报告你用了它**、**检验 median-of-ratios 的假设是否成立**（看 `sizeFactors` 在样本间是否异常）、**把结果与 ANCOM-BC / ALDEx2 做一致性对比**，只把一致的条目当结论。如果结论对方法选择敏感，那结论本身就是不稳健的。

**这一条适用于所有路线。** 扩增子、MetaPhlAn 物种谱、Bracken 丰度、HUMAnN 的功能谱、MAG 的覆盖度、病毒 vOTU 丰度——**全部是相对量，全部具有组成性**。换标记基因或换工具不会让这个陷阱消失。

### 8.5.2 测序深度差异：不统一深度就比较 alpha 多样性，是在比测序深度

**症状**

「处理组的 observed features 与 Shannon 显著低于对照组」——但处理组的样本恰好和某个测序批次重合，而那个批次的读长数普遍更少。

**机制**

低深度样本会**系统性地**低估 richness（observed features）与 Shannon：抽到的序列少了，稀有类群自然检不到。这不是噪声，是方向一致的偏差（bias）。当分组恰好与测序深度相关时，你测出来的完全是深度差异。类似的偏移也发生在 MAG 覆盖度上：低深度样本的 MAG 覆盖度整体偏低，直接比较会得到「病例组某些菌减少」的假象。

**怎么办**

1. **比较 alpha 多样性之前必须统一深度。** 做法是先看 alpha 稀释曲线（`viz_rarefaction_curve`）与每样本读长数分布，选一个**所有或绝大多数样本都能达到**的抽样深度，用它统一抽平。这个取值没有默认，必须自己定并写进方法。
2. **抽平的争议要讲清楚，而不是回避。**
   - 反对抽平的理由（McMurdie & Holmes 2014）：抽平丢弃数据、降低检验效能、把低深度样本的组成变得不稳，而且**不能修复「某些样本本来就读得少」**这一问题。在差异丰度分析里，抽平被证明是有害的——所以**抽平只用于多样性比较，绝不用于计数模型**。
   - 支持抽平的理由：不同深度的样本放在一起比较 richness，**结论本身就是错的**；抽平是把这个偏差消掉的最直接手段。
   - 当前的折中（后续的重新分析）：在多样性比较里，抽平到统一样本量仍然是控制假阳性的有效手段，前提是**报告抽平深度的选择依据**，并且不把它当作万能修正。
3. **替代方案要会用：**
   - **覆盖率（coverage / Good's coverage）**：基于「只出现一次的特征有多少」估计采样完整度，比原始 richness 对深度更稳健。
   - **对深度稳健的指数**：Shannon 比 observed features 稳健一些，但仍受深度影响；Pielou 均匀度、基于覆盖率的插值/外推（iNEXT 一类方法）在统计上比「截断到最小深度」更合理。
   - **把深度作为协变量放进模型**：深度差异不大且样本量大时可行，但必须显式声明，不能默认不处理。
4. **深度差异过大时，正确做法是剔除过浅样本，而不是一味稀释。** 如果最小深度只有几千条序列，抽平到它等于把绝大部分数据扔掉，并让所有样本的多样性估计都很粗糙。这时应如实说明并考虑排除那些样本。
5. **不要用「统一深度」掩盖分组不平衡。** 如果某一组普遍更浅，抽平之后那些样本的组成仍不可靠。正确做法是在方法里说明这一点，并做敏感性分析（例如去掉最浅的样本重跑），而不是靠抽平「抹平」。

**一句话判据**：只要你无法回答「我是怎么处理深度差异的」，你的 alpha 多样性结论就还没有成立。

**三种处理方式的对比（按推荐度排序）**

| 做法 | 适用前提 | 代价 | 什么时候用 |
|---|---|---|---|
| 用覆盖率 / 深度稳健指标 | 深度差异中等（如 2–5 倍） | 需要对指标含义有理解，审稿人可能不熟悉 | 样本量大、不想丢数据 |
| 抽平到统一深度 | 深度差异不大，且最小深度足够大（不损失大半数据） | 丢数据、降效能，**不能修复本来就读得少的样本** | alpha 多样性比较的默认做法 |
| 剔除过浅样本 | 少数样本明显偏浅且原因可查（如 demultiplex 异常） | 样本量下降，可能破坏分组平衡 | 深度差异大且过浅样本集中在少数样本 |
| 把深度作为协变量 | 深度差异不大、样本量充足 | 不消除偏差，只吸收一部分；不能用于 richness 的绝对比较 | 差异丰度分析（不是多样性比较） |

一定要避免的做法：**深度差异 10 倍以上仍然直接比较 alpha 多样性，且不做任何说明。** 这时差异趋势基本由深度驱动。

### 8.5.3 样本量：< 14 个样本的差异丰度分析可靠性极差

**症状**

一共 10 个样本（每组 5 个），做出了 40 个显著差异物种，而且这些物种看起来「很符合预期」。

**机制**

差异丰度分析的检验效能本身就很低，而这类数据的特征数成百上千、零值极多、离散度大。经验上，**总样本数少于 14（每组 7 个左右）时，几乎任何方法都无法稳定检出中等效应，而且结果对方法选择极度敏感**：同一批数据换 ANCOM-BC / ALDEx2 / DESeq2，显著清单的重叠常常低得让人意外。规模化的基准测试也反复显示，不同差异丰度方法在同一数据集上给出的结果差异很大（Nearing 等 2022 年在 38 个数据集上的比较是常被引用的例子）。

小样本还有两个连带效应：单个离群样本可以决定结果，以及批次效应无法与分组分离。

**怎么办**

1. **把样本量当作实验设计问题，而不是分析问题。** 如果研究目标是「找出差异物种」，请在测序前决定样本量；分析阶段无法补救。
2. **小样本时把结论下调为探索性假设**，报告效应量与置信区间，而不是一张「显著物种表」。
3. **做敏感性分析**：多种方法（ANCOM-BC + ALDEx2 + CLR + 常规检验作对照）× 多种过滤阈值，**只把一致的条目当候选**。
4. **不要用 q 值边界讲故事。** 把 q=0.06 写成「有升高趋势」是常见的过度解读；如果检验效能本来就不足，这个「趋势」多半是噪声。
5. **明确写出样本量限制。** 「n=5/组，差异丰度结果仅供假设生成」这样一句话，比任何统计技巧都更有价值。

### 8.5.4 伪重复：同一受试者的多个时间点不是独立样本

**症状**

10 个受试者，每人 5 个时间点，共 50 个样本；病例组与对照组的差异「极其显著」（p = 1e-8）。换一个受试者划分方式重跑，显著性消失。

**机制**

同一个受试者的多个时间点（或多个部位）之间的相似度**远高于**不同受试者之间。把它们当作独立样本，等于把「个体间差异」当成「组间差异」的重复证据：样本量被虚增了 5 倍，而有效样本量其实还是 10。p 值被系统性放大，这是审稿人一眼就能看出的问题。

**怎么办**

1. **在设计阶段就把 `subject` 列写进元数据**（见 8.2.1）。没有它，事后所有补救都做不了。
2. **用混合效应模型**：把受试者作为随机截距（`~ condition + (1|subject)`），让个体差异被显式建模而不是被当成噪声。
3. **或使用限制置换（restricted permutation）**：置换只在受试者内部进行（vegan 里的 `strata` 参数，或 QIIME 2 的相应设置），这样零分布对应的是「受试者内标签随机」而不是「样本标签随机」。
4. **差异丰度分析里也要带上受试者**：ANCOM-BC2 用 `fix_formula` 把批次、受试者写进公式，而不是事后解释。伪重复数据必须把受试者 id 放进模型。
5. **降维图上分不开不代表没有差异，图上分得开也不代表有差异。** 降维图上的一个点是一个样本，不是一个人。

### 8.5.5 批次效应与试剂污染：两件不同的事，不要混为一谈

**症状 A（批次）**

各批次内部组别齐全，但 PCA 上样本按批次而不是按分组聚类，「组间差异」在加入批次项后消失或方向反转。

**症状 B（污染）**

低生物量样本里稳定出现同一个属（`Ralstonia`、`Bradyrhizobium`、`Cutibacterium` 等，随实验室而变），且空白对照里也有。

**机制**

- 不同提取/建库/测序批次的**试剂污染谱不同**，且批次常与操作时间相关，容易与分组部分混杂。**批次信息事后无法从数据里恢复**——这是微生物组项目最常见的不可补救错误之一。
- 试剂与环境污染引入的序列会在低生物量样本里占据可观比例。它们不是随机噪声，而是**有稳定组成的信号**，看起来完全像真实类群。

**decontam 的正确用法与边界**

`amplicon_decontam` 提供三种方法，选择依据是**你手上有什么证据**：

| 方法 | 需要什么 | 适用与风险 |
|---|---|---|
| `frequency` | **同批处理的空白对照** | 最常用；用「读长量随样本生物量变化」的关系判定 |
| `prevalence` | 不需要空白，只用总体检出率 | 容易把稀有真实类群误判成污染物 |
| `combined` | 频率证据 + 浓度数据 | 最稳，但需要两类数据都齐全 |

四条硬边界，越界之后结果没有意义：

1. **没有空白对照也没有浓度数据，就不要跑 decontam。** 强行运行（例如把某些样本手工标记成空白）得到的结果没有意义，却会让流程看起来「做过污染处理」。
2. **不能在相对丰度表或抽平后的表上运行。** 频率法与浓度法都基于读长量随样本生物量的变化关系，归一化会破坏这个关系。**必须用原始计数，且必须在抽平之前。**
3. **采样空白与试剂空白要分开判定。** 混在一起会把采样环境里的真实微生物（例如皮肤样本的环境菌）判成污染物。
4. **decontam 不能解决批次效应。** 它只能识别「与空白对照谱一致」的序列；不同批次的污染谱差异需要在模型里用批次协变量处理。把 decontam 当作批次校正工具是误用。

**还有两类污染物 decontam 抓不到**：如果污染物在所有样本（包括空白）里都是高丰度（引物二聚体、宿主 rRNA、极度常见的环境菌），频率法没有对照信号可用；如果污染与提取批次强相关而没有空白，也无法判定。这两类情况只能靠别的证据（例如与提取批次的相关性）判断。

**报告纪律**：被判定为污染物的序列**不要悄悄删掉**。论文里应报告删除了多少 ASV、占多少读长比例，并给出不删除时的结果。

### 8.5.6 PERMANOVA 与 betadisper 必须一起报

**症状**

「PERMANOVA p = 0.002，说明处理组群落结构与对照组显著不同」——然后从 PCoA 图上指着几个点说「看，分开了」。

**机制**

PERMANOVA（`adonis2`）检验的是**组间距离与组内距离的相对大小**，也就是「组间平均距离是否大于组内平均距离」。它**不是**「两组结构不同」的直接检验。考虑一个常见情形：某一组内部样本彼此差异特别大（例如采样质量参差、批次混杂），这一组的组内距离就大，而组间距离也会随之变大，PERMANOVA 因此显著。这就是**离散度差异被误报成结构差异**。

betadisper（PERMDISP）检验的正是「各组内部离散度是否相等」。两者结论不一致时的处理原则是：**先解决离散度差异，再解释结构差异。** 离散度显著不同通常指向样本质量、批次或采样方式问题，而不是生物学结论。

另外两条同样重要：

- **必须报 R²，不能只报 p。** R² 说明分组解释了多少群落变异。PCoA 前两轴的解释度经常只有 10%–20%，「图上分得很开」可能只是很小的变异在二维投影上被放大。**看着分得开不等于统计显著，也不等于生物学差异大。**
- **PERMANOVA 显著不指向任何具体物种。** 它只说群落整体结构有差异。要找出差异特征必须做差异丰度分析（ANCOM-BC / ALDEx2），不能从排序图推断。

**多组比较时**：用 pairwise 做两两比较必须做多重检验校正，否则组数一多就会「到处都是显著」。

### 8.5.7 分类学与生物学解读的坑

**① ASV 数当物种数。** 见 8.1.2。同时报告 ASV 数与注释到的属/种数。

**② 把「unidentified / uncultured」删掉再画组成图。** 环境样本里 20%–40% 的 ASV 拿不到属名是常态，说明参考数据库覆盖不足，不是流程错误。删掉它们会**系统性高估已知类群的比例**。

**③ 把 SILVA 的注释结果与 MAG/GTDB 路线的分类直接比较。** 两套体系对高级分类单元（纲、目）的划分不同，看起来「同一个属在两条路线里丰度差很多」，很多时候只是命名体系不同。跨体系比较要么统一到一套，要么退到属以上层级并做名称映射。

**④ 把 GTDB 的占位名当物种名。** 形如 `UBA` 系列或 `sp` 编号的名称只是参考树上的占位标识。正确表述是「与某参考基因组 ANI 为 X% 的未描述类群（GTDB R2xx）」。

**⑤ 用 GTDB-Tk 的 ANI 判断两个 MAG 是否同种。** GTDB-Tk 给的是「相对最近参考」的 ANI 估计，不是成对基因组 ANI。判断同种要用成对 ANI 工具，或统一在去冗余步骤（dRep）里处理。

**⑥ 用 MAG 名录比较不同样本的群落组成。** MAG 名单只有被组装、被分箱的类群才会出现，低丰度物种系统性缺席。这是**丰度偏倚**，不是随机缺失。群落组成比较属于读长级分类（Kraken/MetaPhlAn）或扩增子的任务。

**⑦ 把 MAG 的基因缺失当成「该基因组没有这个基因」。** MAG 是**草图（draft）**。缺失只能解释为「本次组装没拼出来」，不能解释为「不存在」。用低完整度 MAG 做基因存在/缺失与通路完整度分析会产生系统性假阴性。

**⑧ 用 contig N50 评价组装质量、用 bin 数量评价分箱质量。** 两个都是错的。N50 由群落复杂度决定；bin 数量多可能只是同一个基因组被切碎（每个碎片看起来「完整度还行」）。判断依据是 CheckM2 的完整度/污染度分布，以及基因组大小分布。

**⑨ 低丰度物种「不存在」。** 覆盖度 ≲ 1× 的物种基本分不出来，也常常检不到。报告里应说明**检出限**，而不是把「没分出来」解释成「不存在」。同样地，MetaPhlAn 的「没检出」不等于不存在（见 8.1.3）。

**⑩ 用「病毒丰度 ÷ 宿主 MAG 丰度」当诱导率。** 两者的 DNA 池、提取与测序过程不同，这个比值没有明确的生物学含义。诱导实验需要专门的实验设计。

**⑪ 用测序读长比例推算真菌:细菌生物量比。** 16S 与 ITS 的拷贝数、扩增效率、提取效率都不同，读长比例最多反映「相对扩增信号」。要谈 F:B 比必须用 qPCR。

**⑫ 把病毒 unclassified 比例当质控指标。** 病毒序列里很大一部分无法分类（没有参考），这是领域现状而不是流程缺陷。为了降低这个比例而放宽阈值，会损害结论可信度。

### 8.5.8 流程与文件层面的坑

这些坑的共同点是：**不报错**，因此只能靠纪律避免。

| 坑 | 症状 | 机制与对策 |
|---|---|---|
| manifest 路径/格式写错 | 导入失败，或质量分数整体偏移 | `forward-absolute-filepath` 表头拼写与**绝对路径**是最常见失败点；Phred33 与 Phred64 混用会让后续所有质量阈值的含义都错 |
| 样本名不一致 | 报错，或更糟：静默丢样本 | 大小写、连字符与下划线、前后空格、`.fq.gz` 后缀。合并前先做一次集合差集比较并打印差异；构建对象后立刻核对样本数 = 元数据行数 = 表的列数 |
| 导入成功就当数据可用 | 某个样本读长数低一个数量级 | 必须先看 demux summarize。某样本远低于同批其他样本通常是 demultiplex 或 index 问题，**是数据错误不是离群值**，应重跑拆分或联系测序方 |
| 引物没切干净 | ASV 长度分布异常整齐；嵌合体偏多 | 残留引物成为所有 ASV 的共有前缀。16S V4 插入片段约 253 bp，长度分布明显偏离预期时先怀疑引物或建库 |
| 把 `.qza` 当通用格式传给别人 | 对方打不开 | 它是容器（数据 + 类型元数据），跨工具交换一律走 `qiime tools export`，并记录导出用的 `--type` |
| 数据库版本没记 | 结果无法复现；换库后的变化被误读成生物学差异 | 参考数据库版本与构建日期的权重常高于软件版本。SILVA 138.x、Greengenes2 发布版本、UNITE 数据集版本（动态数据集会随日期变化）、Kraken 库类型、MetaPhlAn index、GTDB R2xx、CheckM2 模型版本都要记 |
| 去宿主不彻底 | 稳定的假阳性物种 | 宿主读长被分到近缘微生物上。宿主占比高的样本必须先做去宿主并复核 |
| 参考基因组与注释不同版本 | 比对能跑、计数能出结果，但坐标是错的 | 下载时记录 accession、版本与日期 |
| 把 0 字节文件当作「已完成」 | 下游拿到空数据，错误位置远离真正原因 | 断点判据必须是「文件存在**且非空**」（见[第 0 章](00-overview-and-learning-path.md) 0.5） |
| 用不同参考集合定量不同样本 | 样本间数字不可比，且矩阵里完全看不出来 | 同一个 MAG 集合必须贯穿所有样本；重新分箱后必须全部重新定量 |

### 8.5.9 一个完整的翻车案例：六个陷阱是怎么串起来的

下面这个案例是真实项目里反复出现的形态。它值得完整读一遍，因为**单看每一步都不算错**，错在它们的叠加。

**项目**：比较「处理组 vs 对照组」的肠道菌群差异。16S V4 扩增子，两组各 8 个样本，共 16 个。测序分两批完成，第一批做了对照组 6 个 + 处理组 2 个，第二批做了剩下的。没有空白对照。元数据表里只有 `sample-id` 和 `group` 两列。

**分析**：DADA2 去噪 → SILVA 注释 → 抽平到最小深度 → 在相对丰度上做 Mann-Whitney（用 `multipletests` 默认的 `'hs'`）→ PCoA + PERMANOVA → 画组成堆叠图。

**结果**：137 个属显著，其中 62 个「显著升高」、75 个「显著降低」；PERMANOVA p = 0.001，R² = 0.18；PCoA 上两组明显分开。作者写：「处理显著改变了肠道菌群结构，X 属显著富集。」

**逐步拆开看，哪些结论还站得住**

| 步骤 | 问题 | 属于哪一条 |
|---|---|---|
| 元数据只有两列 | 没记**批次**，而批次与分组部分混杂（第一批对照组多）；事后无法补救 | 8.5.5 |
| 没有 `subject` 列 | 如果是同一批动物的多个时间点，就是伪重复；此处无法判断 | 8.5.4 |
| 没有空白对照 | decontam 无法运行；低丰度序列来源不明 | 8.5.5 |
| 抽平后做 Mann-Whitney | **抽平只用于多样性比较，不用于统计检验**；而且检验是在相对丰度上做的 | 8.5.1、8.5.2 |
| 相对丰度上做 Mann-Whitney | 组成性 → 假阳性成片出现；137 个显著属里绝大部分是这个机制产生的 | 8.5.1 |
| `multipletests` 用 `'hs'` | 控制 FWER，在几百次比较时过严；这里却仍显著，说明信号（或偏差）很大 | 8.5.1 |
| 16 个样本 | 总样本数刚到 14 的门槛附近，差异丰度结果**高度依赖方法选择** | 8.5.3 |
| PCoA「明显分开」 | 前两轴解释度未知；R² = 0.18 意味着分组只解释 18% 的变异 | 8.5.6 |
| PERMANOVA 只报 p | 未做 betadisper；两批测序混合很可能造成组内离散度不同 | 8.5.6 |
| 「X 属显著富集」 | 组成性数据上，X 的份额上升可能只是别的东西少了；且从排序图/组成图不能推断具体物种 | 8.5.1、8.5.6 |

**哪些结论其实还站得住**：只有两条——「两组的群落结构在这个样本量下可能不同（R² = 0.18，p = 0.001）」以及「X 属在处理组的**份额**更高」。注意「份额更高」不等于「绝对量更多」，也不等于「别的菌没变」。

**如果重做一次，最小代价的修法是**：

1. 把批次写进模型（`~ batch + group`），并检查批次与分组的混杂程度——如果完全混杂，这个分析在统计上无解。
2. 差异丰度改用 ANCOM-BC 或 ALDEx2（在**原始计数**上，不抽平），并用 `'fdr_bh'` 校正；同时跑 CLR + 常规检验作为对照，只把一致的方向性结论保留。
3. 做 betadisper，确认显著不是离散度差异造成的。
4. 报告 PCoA 的轴解释度与 PERMANOVA 的 R²，而不是只报 p。
5. 把「样本量 16、方法间一致性有限」显式写进局限。
6. 如果样本还能补，补空白对照与更多生物学重复——这两件事的收益远大于任何分析技巧。

**这个案例的要点是：出错的不是某一个参数，而是「把相对丰度当成绝对量、把样本当成独立观测、把显著当成结论」这一整套默认习惯。** 8.5.10 的清单就是用来打断这套习惯的。

### 8.5.10 交付前的自检清单

把这份清单贴在分析记录里，每一项都能用一句话回答「是」或「否」：

- [ ] 元数据里有 `batch`、`subject`、`control_type` 三列（低生物量项目还有空白对照行）
- [ ] 所有参考数据库与软件版本已记录（**含构建日期**）
- [ ] 引物已切除，并在长度分布上验证过
- [ ] decontam 在**原始计数**上运行，且用同批空白对照
- [ ] 比较 alpha 多样性前已统一深度，并写明抽平深度或替代方案
- [ ] beta 多样性同时报告了 PERMANOVA 的 **R² 与 p**，以及 betadisper
- [ ] 差异丰度用了组成性感知方法（CLR/ILR、ANCOM-BC、ALDEx2），不是裸的 t 检验
- [ ] 如果用了 DESeq2，已检验归一化假设并与组成性方法做过一致性对比
- [ ] 报告了效应量与置信区间，不只是 p/q 值
- [ ] 样本量 < 14 时，结论已明确标注为探索性
- [ ] 伪重复已用混合效应模型或限制置换处理
- [ ] MAG 报告了 CheckM2 版本、去冗余前后的质量分布、以及「MAG 是草图」的前提
- [ ] 病毒报告了 vOTU 阈值、CheckV 质量等级分布，且没有跨项目比较绝对数量
- [ ] 关键结论做过敏感性分析（换方法 / 换过滤阈值 / 去最浅样本）
