# 第 5 章 分类鉴定与物种注释

## 5.1 这一层要回答什么问题

「这是什么菌」听起来像一个简单问题，实际上是四个不同层次的问题，它们的证据强度、所需数据和结论强度完全不同：

| 层次 | 典型问法 | 主要方法 | 结论强度 |
|---|---|---|---|
| 高阶归属（域/门/纲/目/科） | 「这个 MAG 属于哪个门？」 | 标记基因分类、k-mer 分类 | 较强，参考库覆盖通常足够 |
| 属级归属 | 「这是不是 *Klebsiella*？」 | 标记基因分类 + ANI | 较强，但属的边界本身有争议 |
| 种级归属 | 「这是不是 *K. pneumoniae*？」 | ANI（≥95%）、GTDB-Tk 的种级分配 | 中等：取决于参考库覆盖与阈值约定 |
| 种以下（菌株） | 「这两株是不是同一次暴发？」 | **不属于本章**：cgMLST、core-SNP（第 7 章） | 需要读长层面的数据与方法 |

**本章只处理前三个层次。** 把菌株级问题交给这一层会得到「同一个种」这个无法用于结论的答案；反过来说，用菌株级方法去回答属级问题也是资源浪费。

### 这一层最重要的一句话

> **分类结果不是基因组的固有属性，而是「这个基因组与某个参考体系比较的结果」。**

这句话有三个直接推论，它们贯穿本章：

1. **体系必须说明。** GTDB 与 NCBI 是两套不同的分类体系：GTDB 的种以 ANI 95% 簇为基准划分，因此会出现「GTDB 有 `s__` 名称而 NCBI 里没有对应种名」或反之的情况，属名与种名也常被重排。报告里写「*Klebsiella* sp.」时必须说明是哪个体系下的写法。
2. **数据库版本必须说明。** GTDB-Tk 的参考数据版本（R2xx）会改变分类命名与 ANI 计算，跨批次用不同版本注释会让「新种 / 新属」的结论无法复现。16S 数据库（SILVA、NCBI 16S RefSeq、EzBioCloud）的收录范围与命名不同，同一条序列的最佳命中可能属于不同物种。
3. **分类正确 ≠ 基因组纯净。** 分类注释回答「它像谁」，不回答「它是不是纯的」。一个被污染的基因组可以给出一个非常确定的分类结果（因为污染比例低，或者污染物恰好是近缘物种）。质量与污染判定必须单独做（第 4 章）。

### 这一层的输出会流向哪里

分类结果不是终点，它是三个下游判断的输入：

- **能不能做下游泛基因组？** 输入必须是**同一物种**的一组基因组。跨物种的泛基因组没有意义（同源关系会混入直系同源与旁系同源）。
- **能不能用这个参考做比对与变异检出？** 用同属不同种的参考会让「SNP 数」变成种间差异（可能几十万），此时任何过滤阈值都失去意义。
- **结论应该报到哪一级？** 一份完整度 70% 的 MAG 通常只支持属级或科级结论；把它报到种是把不确定性藏起来。

## 5.2 输入、输出与中间文件长什么样

### 输入

| 类型 | catalog 类型 id | 说明 |
|---|---|---|
| 基因组或 MAG 序列 | `genome-fasta` | 批量时通常一个文件一个基因组；后缀必须统一 |
| 查询基因组 | `genome-fasta` | ANI 计算中的 query |
| 参考基因组集合 | `reference-genome` | ANI 的参考库；选择直接决定结论 |
| 查询 16S 序列 | `cds-fasta` | 从基因组提取，或来自扩增子（两条不同路径） |
| 清理后读长 | `clean-reads` | 读长层面的分类（第 8 章）与污染筛查 |

### 输出

> 目录命名说明：`05_taxonomy` 与第 8 章宏基因组流程使用的 `05_taxonomy/gtdbtk/...` 保持一致；这样「从单菌基因组鉴定」与「从 MAG 鉴定」两套流程的结果能放在同一个命名规则下比较，也便于下游脚本复用。

```
05_taxonomy/
├── gtdbtk/
│   ├── gtdbtk.bac120.summary.tsv     # 每个基因组一行：分类串 + 最近参考 + ANI
│   ├── gtdbtk.bac120.classify.tree   # 标记基因树（展示用，不是系统发育结论）
│   ├── gtdbtk.bac120.msa.fasta       # 标记基因比对
│   └── identify/                     # 中间文件，体积大（每基因组 GB 量级）
├── ani_all.tsv                       # fastANI 成对结果
├── ani_best.tsv                      # 每个 query 的最佳命中（自己筛出来）
├── sample.rrna.gff                   # barrnap 的 rRNA 坐标
├── sample.16s.fasta                  # 按坐标提取的 16S 序列
├── sample.blast16s.hits.tsv          # 16S 比对结果（含相似度与覆盖度）
├── refs.msh + sample.mash.dist.tsv   # Mash 粗筛
└── genomes.sig + cmp.csv             # sourmash 相似度矩阵
```

### 各输出的关键列与读法

| 输出 | 关键字段 | 怎么读 |
|---|---|---|
| GTDB-Tk `*.summary.tsv` | `classification`（`d__`→`s__` 的完整串）、`closest_genome_reference`、`*_ani`、`*_af` | 分类串**可能只到 `p__` 或 `c__`**，这不是「分类失败」而是数据不足；`s__` 后面可能是空或编号，表示 GTDB 里没有命名种 |
| GTDB-Tk 标记基因树 | 分支拓扑 | 它是**快速树**：没有去重组、没有支持度检验，标记集也不是为该类群优化的。**不适合作为系统发育结论** |
| fastANI 结果 | `query`、`reference`、`ANI`、`mapping fragments`、`total fragments` | ANI 是**全基因组平均值**，会掩盖局部差异；映射片段比例低时数值不可信 |
| barrnap GFF | 类型（16S / 23S / 5S / 部分命中）、起止坐标 | 必须按注释类型筛选——把 23S（约 2.9 kb）当 16S 去比对会得到奇怪的「新物种」 |
| 16S BLAST 结果 | `pident`、`length`、`qcovhsp`、`evalue`、`ssciname` | **相似度必须与覆盖度一起看**：覆盖度只有 80% 的 99% 命中不能作为鉴定依据 |
| Mash 距离 | `distance`、`p-value`、共享哈希数 | 它是「Mash 距离」，**不是 ANI**；换算只在种边界附近大致成立 |

### 一个可执行的鉴定流程（有基因组时）

```bash
T=16

# 1) 标准化分类注释（批量，一次跑完一个目录）
gtdbtk classify_wf --genome_dir 02_assembly/filtered/ \
        --out_dir 05_taxonomy/gtdbtk --extension fna --cpus $T
# 中间文件很大：大批量运行时用 --scratch_dir 指到大磁盘

# 2) 种边界与最近邻的定量证据
ls 02_assembly/filtered/*.fna > 05_taxonomy/query_list.txt
ls refs/*.fna                  > 05_taxonomy/ref_list.txt
fastANI --ql 05_taxonomy/query_list.txt --rl 05_taxonomy/ref_list.txt \
        -o 05_taxonomy/ani_all.tsv -t $T

# 3) 每个 query 的最佳命中（结果表动辄几十万行，先取最佳）
sort -t$'\t' -k1,1 -k3,3nr 05_taxonomy/ani_all.tsv \
  | awk -F'\t' '!seen[$1]++' > 05_taxonomy/ani_best.tsv

# 4) 交叉核对：GTDB-Tk 的 ANI 列与 fastANI 的结果应大致一致
#    不一致时先查参考库是否包含同一个最近邻

# 5) 需要 16S 路线时（提交要求、与旧文献可比、或只有标记基因可用）
barrnap --kingdom bac --threads 8 02_assembly/${S}.filtered.fasta \
    > 05_taxonomy/${S}.rrna.gff
awk '$3 ~ /16S/ && ($5-$4) > 1200' 05_taxonomy/${S}.rrna.gff \
    > 05_taxonomy/${S}.16s.gff
bedtools getfasta -fi 02_assembly/${S}.filtered.fasta \
    -bed 05_taxonomy/${S}.16s.gff -fo 05_taxonomy/${S}.16s.fasta
seqkit stats -a 05_taxonomy/${S}.16s.fasta   # 长度是否接近 1.5 kb

# 6) 数据库非常大时，先用 k-mer 方法粗筛候选近缘，再精算 ANI
mash sketch -k 21 -s 10000 -o 05_taxonomy/refs refs/*.fna
mash dist -p $T 05_taxonomy/refs.msh 02_assembly/${S}.filtered.fasta \
    > 05_taxonomy/${S}.mash.dist.tsv
```

## 5.3 工具拼装思路（含选择决策树）

### 先问三个问题

1. **输入的可靠性如何？** 是完成图、高质量草图、还是完整度 70% 的 MAG？这决定结论能报到哪一级。
2. **结论要跟谁比？** 要与已发表数据比（需要标准化体系、注明版本）、要与旧文献的 16S 结果比、还是要与本地参考库比？
3. **需要回答的是「是不是同一个种」还是「最近邻是谁」？** 前者需要阈值判据（ANI），后者只需要排序（Mash / sourmash 即可）。

### 决策树

```
你手上是什么？
├── 基因组 / 高质量草图（完整度 > 90%）
│   ├── 需要标准化、可跨实验室比较的分类命名
│   │      → GTDB-Tk classify_wf
│   │         注意：输出的是 GTDB 体系，与 NCBI 命名不完全一致
│   ├── 需要「这两个基因组是不是同一个种」的定量判据
│   │      → fastANI（ANI ≥ 95% 通常视为同一个种）
│   ├── 需要「最近邻是谁」且参考库很大（上千到上万基因组）
│   │      → Mash / sourmash 粗筛 → fastANI 精算
│   └── 需要与旧文献的 16S 结果衔接，或提交材料要求 16S
│          → barrnap 提取 16S → BLAST 比对参考库
│             同时明确说明 16S 的分辨率不足（很多类群区分不到种）
├── MAG（完整度可能只有 50–80%）
│   ├── 完整度 > 90% 且污染度 < 5% → 按基因组处理，但报告里注明 MAG 来源
│   ├── 完整度中等（70–90%）→ GTDB-Tk 通常还能给到属级
│   │     不要硬报到种；「只到 p__ / c__」是数据不足的正常结果
│   └── 完整度低 / 标记基因缺失太多
│          → 先改善组装，或改用读长层面的物种谱（第 8 章）
│             注意：MAG 里找不到 16S 是常态，不能据此说该菌没有 16S 基因
└── 只有读长（没有组装）
       → 读长层面的分类（Kraken 2 / MetaPhlAn，第 8 章）
          与本章的基因组层面方法结论口径不同，不能混着报

需要菌株级区分？
└── 立刻离开本章：cgMLST（var_typing_cgmlst）或 core-SNP（comp_snp_dist）
      ANI ≥ 99.9% 的两株菌差异可能在几十到几千个 SNP 之间
      「ANI 报 100.0」不代表同一株

参考库从哪里来？
├── 已经有明确的研究对象 → 用该物种的代表基因组集（并记录来源与日期）
├── 需要覆盖广泛类群 → GTDB / RefSeq 的代表基因组（体积大，需提前规划磁盘）
└── 千万不要用"随手下载的一批基因组"当参考库：
      参考库的选择直接决定最近邻与 ANI，必须版本化管理（util_download_ref）
```

### 各方法的分工与不可替代性

| 方法 | 回答什么 | 输入层面 | 典型场景 | 关键限制 |
|---|---|---|---|---|
| GTDB-Tk | 标准化分类命名（域→种）+ 最近参考 | 蛋白/核酸（内部预测基因） | 批量基因组与 MAG 的分类注释 | 体系与 NCBI 不同；不能给种以下分型；树的用途有限 |
| fastANI | 「是不是同一个种」 | 核酸 | 新分离株的种级确认；近缘检索 | 近缘处饱和（不能区分菌株）；不同实现数值不可互换 |
| Mash | 快速距离，粗筛 | k-mer 草图 | 上万参考基因组里找候选 | 默认草图分辨率不足；距离≠ANI |
| sourmash | Jaccard / containment，构成解释 | k-mer 草图 | 一小组基因组的相似性聚类；宏基因组构成解释 | 距离远时失真；compare 与 gather 语义不同 |
| 16S 提取 + BLAST | 标记基因层面的归属 | 核酸 | 与旧文献衔接、提交要求、只有标记基因时 | 分辨率不足；多拷贝；rRNA 区组装易错 |
| 读长分类（第 8 章） | 群落组成 | 读长 | 宏基因组、污染筛查 | 与基因组层面口径不同，不可直接拼接 |

### 关于「体系选择」这个容易含糊过去的问题

三套体系的实际差异需要说清楚，否则写论文时会踩坑：

| 体系 | 特点 | 什么时候必须用 |
|---|---|---|
| GTDB | 以 ANI 95% 簇定义种；分类命名经过大规模重排；未命名种用编号表示 | 需要标准化、可复现、跨实验室可比的基因组层面分类 |
| NCBI | 传统分类学命名，与分类学委员会命名挂钩；新种需要正式发表与命名 | 提交 NCBI、与临床微生物学文献衔接、需要正式种名 |
| 16S 参考库（SILVA / NCBI 16S RefSeq / EzBioCloud 等） | 基于标记基因序列与各自的命名约定 | 与旧文献的 16S 鉴定结果比较；扩增子分析 |

**三套体系不能拼接。** 一句「该菌属于 *Klebsiella pneumoniae*（GTDB 命名为 *K. pneumoniae*，NCBI 中为 *K. pneumoniae* sensu stricto）」如果写混了，会变成一条无法核对的陈述。规范做法是：**明确选一套作为主口径，其他体系的对应关系作为附注。**

## 5.4 关键参数取舍

### GTDB-Tk

| 参数 | 默认 | 建议与理由 |
|---|---|---|
| `classify_wf` vs `classify` | 无 | `classify_wf` 会建标记基因树，中间文件大、耗时更长；**只要分类结果时用 `classify`**，一次能省下大量时间与磁盘 |
| `--extension` | 以版本为准 | 批量目录时只处理匹配后缀的文件。`.fa` / `.fasta` / `.fna` 混放会**静默漏掉样本**，建议项目内统一后缀 |
| `--min_perc_aa` | 10 | 参与比对的标记基因氨基酸比例下限；低于它该基因组会被跳过或只给出高阶分类。远缘或碎片化基因组可适当放宽，但结果可靠性随之下降 |
| `--cpus` | 以版本为准 | 比对与建树阶段对线程敏感 |
| `--scratch_dir` | 临时目录 | 中间文件很大（每基因组 GB 量级），大批量运行必须指到大磁盘 |
| `--outgroup_taxon` | 无 | 仅 `de_novo_wf` 使用：定根外群；选错会改变树的根位置（**分类串不受影响**），参数细节以官方文档为准 |
| 参考数据版本（R2xx） | 随安装包 | **必须在方法学中写明**；不同版本会改变分类命名与 ANI 计算，跨批次数据不可混用版本 |

一个部署经验：GTDB-Tk 需要单独下载参考数据（数十 GB 量级），且**下载与安装是两个步骤**。把参考数据放在共享目录并记录 release 号与下载日期，比每个项目重新下载更省事也更可复现。

### fastANI

| 参数 | 默认 | 建议与理由 |
|---|---|---|
| `--minFraction` | 0.2 | 至少需要多少比例的查询片段能映射上才输出 ANI；降低它可以比较更远的关系，但数值偏差变大（默认值以官方文档为准） |
| `--fragLen` | 3000 | 片段长度；调小对碎片化组装更友好但更慢，结果也会变化，**跨运行必须固定** |
| `-k / --kmer` | 16 | 映射阶段的 k-mer 长度；改动会影响敏感度（以官方文档为准） |
| `-t / --threads` | 以版本为准 | 参考基因组数量大时内存与时间近似线性增长 |
| `-q` / `-r` 与 `--ql` / `--rl` | 单文件模式 | 批量必须用列表文件；参考库上千时**建议先用 Mash/sourmash 粗筛再精算**，否则组合数会爆炸 |

### Mash

| 参数 | 默认 | 建议与理由 |
|---|---|---|
| `-k` | 21 | k 越小越能容忍序列差异（适合较远关系的粗筛），k 越大对近缘区分越好但灵敏度下降；物种级常用 21，菌株级常配 31 与更大的草图 |
| `-s` | 1000 | 草图大小。**近缘比较必须加大（如 10000 或更多）**，否则距离被随机误差主导，「两株菌距离为 0」会频繁出现 |
| `-p` | 以版本为准 | `dist` 很快，参考库很大时 I/O 也会成为瓶颈 |
| `mash screen` 的一致性/胜者模式 | 以官方文档为准 | 读长筛查时用于控制最小一致性与是否 winner-takes-all；不同设置会改变敏感度 |
| 草图参数固定 | 必须 | k 与 `-s` 不同的草图之间距离**不可比较**；批量项目应把参数写进流程并记录 |

一句必须记住的换算边界：`k=21` 时 Mash 距离 0.05 大致对应 ANI 95%（即种边界），0.02 以内通常属于同种。这是**近似关系而非等式**，距离越大误差越大；用于物种归属判断时应该用 ANI 复核，并且报告里要写「Mash 距离」而不是含糊地写成「ANI」。

### sourmash

| 参数 | 默认 | 建议与理由 |
|---|---|---|
| `-p k=31,scaled=1000` | k=31, scaled=1000 | 一次 sketch 可含多个 k，但**比较时只会用相同的 k/scaled**。scaled=1000 适合物种级筛查；近缘（>99% ANI）比较需要更小 scaled（如 100） |
| `--singleton` | 关闭 | 把每条读长当成独立签名；默认把文件内所有序列合并为一个签名（宏基因组要的正是合并） |
| `compare --ani` | 关闭 | 直接输出 ANI 估计而不是 Jaccard；**距离越远该换算越不可靠** |
| `gather` 的阈值与结果数 | 以官方文档为准 | 控制解释深度与最少贡献碱基数；阈值定得太低会把噪声当成物种 |
| 子命令选择 | — | `compare` 算两两 Jaccard（一组基因组之间的相似性）；`gather` 算 containment 并贪心解释混合样本（宏基因组）。**用错子命令会得到看似合理但语义错误的结果** |

### 16S 提取与比对

| 参数 | 默认 | 建议与理由 |
|---|---|---|
| `barrnap --kingdom` | 以版本为准 | `bac` / `arc` / `euk` / `mito`；选错域会漏掉或误判。样本里混有古菌或真核序列时建议分别运行再合并 |
| 部分命中的长度/拒绝阈值 | 以官方文档为准 | 放宽会得到更多被打断的片段，**鉴定前必须按长度筛** |
| 长度门槛 | 建议 ≥ 1200 bp | 完整 16S 约 1.5 kb；短于 1200 bp 的片段用于鉴定会把相似度系统性拉低 |
| `blastn -outfmt` | 0（成对文本） | 脚本化**必须用 6（表格）**；列由你指定顺序，务必把列定义写进方法或随结果保存 |
| `blastn -max_target_seqs` | 以版本为准 | **它限制的是参与输出的命中数，而不是「最优的 N 条」**；做鉴定时应给足（见 5.5 坑 5） |
| `blastn -qcov_hsp_perc` | 0 | 按 HSP 覆盖度过滤；鉴定场景设 90 以上可显著减少部分命中造成的假象 |
| `blastn -perc_identity` | 0 | 搜索阶段就设相似度下限（如 90）；设了之后低相似度的真信号也看不到，**鉴定时通常先不设、事后筛** |
| 数据库选择 | 无 | NCBI 16S RefSeq / SILVA / EzBioCloud / Greengenes 的序列集与命名不同，最佳命中可能不同；**数据库版本必须记录** |

### 阈值的来历（这是本节的重点）

数字必须带理由，否则读者无法判断该不该沿用：

| 阈值 | 含义 | 来历与边界 |
|---|---|---|
| ANI ≥ 95% | 通常视为同一个种 | 大致对应 70% dDDH（DNA-DNA 杂交的黄金标准）。这是**基因组时代的物种界定惯例**，不是分类学上的正式定义；命名仍需要分类学证据与正式发表 |
| ANI 80–95% | 同属不同种 | 同上；属的边界比种更宽松，且不同属的实际情况差异很大 |
| ANI < 80% | 一般不再有意义 | fastANI 在这个距离上映射片段比例会很低，结果偏差大 |
| 16S ≥ 99% | 提示同种 | **惯例而非标准**；不同类群的种内 16S 差异差别很大（有的种内差异接近 0，有的超过 1%） |
| 16S 97–99% | 提示同属 | 同上；这个区间的判读最不可靠 |
| 16S < 95% | 提示更高层级差异 | 属以上关系的粗略指示 |
| Mash 距离 ≤ 0.05（k=21） | 大致对应 ANI 95% | 近似换算，随 k 与距离变化；**不能替代 ANI** |

**这些阈值的共同性质是：它们是社区惯例，用来快速判断，不是用来下定义。** 报告物种归属时，规范写法是「ANI = 96.3%（fastANI 1.3x，参考库见补充材料）」，而不是「鉴定为 *X*」。

## 5.5 常见坑

这一节讲**跨步骤的系统性问题**。

### 坑 1：分类结果是数据库版本的函数，而被当成基因组的属性

同一份基因组在不同版本的 GTDB 下可能得到不同的分类串；同一条 16S 在不同数据库里的最佳命中可能属于不同物种；同一个 MAG 在不同 GTDB-Tk 版本下的「最近参考」与 ANI 值都会变。

由此得到一条实践规则：

> **分类结论必须写成「在这个体系、这个版本下得到的结果」**，而不是「这就是它的分类」。跨批次比较前先统一版本；做不到统一时，在方法里说明版本差异，并检查差异是否影响关键结论。

### 坑 2：混用 GTDB 与 NCBI 的名称

GTDB 与 NCBI 的差异不是命名风格的差异，而是划分依据不同：

- GTDB 的种以 ANI 95% 簇为基准，因此经常出现「GTDB 里只有编号（`s__` 后面是空的或一个编号），NCBI 里有正式种名」；
- 属名与种名也常被重排（同一基因组在两套体系下可能属于不同的属）；
- 把一个体系的属名与另一个体系的种名拼在一起，会得到在任何体系下都不成立的名称。

规范做法：选定一套体系作为主口径，在结果表里保留完整的分类串（`d__Bacteria;p__...;s__...`），并在方法中写明体系与版本。需要与另一套体系对应时，单独给出映射表，而不是在正文里混用。

### 坑 3：ANI 的三类误用

**(a) 用 ANI 区分菌株。** ANI 在近缘处饱和：两株 ANI 都报 100.0 的菌仍可能有数千个 SNP。暴发调查、传播链推断必须用 core-SNP 或 cgMLST。一条可操作的判据：

> ANI 回答「是不是同一个种」，cgMLST / core-SNP 回答「是不是同一株」。两者不能互相替代。

**(b) 跨 ANI 实现比较数值。** fastANI / ANIb / ANIm / OrthoANI / dDDH 的算法不同，同一对基因组的数值差异可达零点几个百分点——正好落在种边界附近时，结论会翻转。方法学里必须写明工具与参数。

**(c) 把「ANI 不是 100」当差异证据。** 测序错误、组装差异与重复区处理都会让同一菌株的 ANI 变成 99.9x。这属于过度解读。

还有一条相关限制：**ANI 是全基因组的平均值，会掩盖局部差异。** 同种菌株之间可以有整段基因组岛的有无，以及完全不同的质粒。ANI 高不代表基因内容一致——那要看泛基因组或基因存在/缺失矩阵（第 7 章）。

### 坑 4：16S 路线的五个具体陷阱

16S 是最容易被过度解读的标记。它的限制需要逐条说清：

1. **拷贝数不止一个。** 细菌基因组通常有多个 rRNA 操纵子（16S 拷贝数从 1 到十几个），「提取 16S」得到的是序列集合而不是一条。不同拷贝之间可能有明显差异；只取第一条会让鉴定结果取决于运气。正确做法是把所有拷贝都取出、分别比对，并报告拷贝之间的差异。
2. **rRNA 区是组装的重灾区。** 短读长组装常在此塌缩或断开，提取出来的「16S」可能是嵌合体或只有一半。拿到序列先看长度（完整 16S 约 1.5 kb）以及是否跨越 contig 边界。
3. **分辨率有限，很多类群区分不到种。** *Bacillus cereus* group、*Escherichia*/*Shigella*、部分 *Borrelia* 与 *Mycobacterium* 即使全长 16S 也难以区分。这类样本必须用基因组层面的方法（ANI、core-SNP）。
4. **MAG 里经常一无所获。** rRNA 在宏基因组组装与分箱中都容易被丢掉。MAG 里找不到 16S 是常态，**不能据此说该菌没有 16S 基因**。
5. **容易把 23S 当成 16S。** barrnap 同时会报 23S/5S 与部分片段；把 23S（约 2.9 kb）误当 16S 去比对，会得到奇怪的「新物种」结果。务必按注释类型筛选。

### 坑 5：BLAST 的 `-max_target_seqs` 不是「返回最好的 N 条」

这是一个被专门讨论过的参数误解：它按数据库扫描顺序保留先满足阈值的命中，**可能漏掉得分更高的序列**。做物种鉴定时把该值设小（例如 5）会直接改变结论。

规范用法：鉴定场景给足命中数（例如 50），事后在本地按相似度与覆盖度筛。同时注意「只看相似度不看覆盖度」是鉴定中最常见的过度解读——片段化的 16S（例如只有 700 bp）很容易出现 99–100% 的命中，但那往往只是保守区匹配。

### 坑 6：嵌合序列表现为「分散的多个高相似度命中」

嵌合 16S（PCR 或组装产生）会产生一种特征模式：**与多个不同物种各有一段高相似度**，而不是单一最佳命中。看到「最佳命中覆盖度低且候选分散」时，应先做嵌合检测，而不是挑一个最像的报上去。

同样的逻辑适用于组装产物层面：一段嵌合 contig 会让分类结果在不同区域指向不同类群。

### 坑 7：低完整度基因组不要急着做鉴定

分类学注释与质量评估有**依赖关系**：完整度/污染度不达标的基因组（例如完整度 < 90%）做鉴定，结果可能不可靠。具体表现是：

- **标记基因缺失太多** → 分类失败，或只给出高阶分类（`p__` / `c__`）；
- **污染序列存在** → 污染物的标记基因参与分类决定，可能把结果拉向另一个类群；
- **碎片化严重** → 标记基因可能落在 contig 边界，命中不稳定。

看到「只到 `p__` / `c__`」**不要硬套到种**，先回看 `--min_perc_aa` 的提示与基因组完整度。这不是分类工具的问题，是输入的问题。

### 坑 8：把 GTDB-Tk 的标记基因树当系统发育结论

GTDB-Tk 输出的树是基于标记基因的快速树：没有去重组、没有支持度检验，标记集也不是为该类群优化的。它可以用于**展示与粗分组**，但不能作为系统发育结论。正式建树需要另做完整流程（比对 → 修剪 → 选模型 → 建树 → 支持度评估），见第 7 章。

### 坑 9：用错误的参考做下游比对

这一条跨越第 5 章与第 7 章：**分类结论直接决定你能不能用某个参考基因组做比对与变异检出。** 用同属不同种的参考会让「SNP 数」变成种间差异（可能几十万），此时任何过滤阈值都失去意义；SNP 距离是在参考坐标系下计算的，换参考后距离矩阵不同，传播结论可能改变。

所以「先用 ANI 确认样本与参考的关系，再做比对」不是可选的礼节，而是前置条件。

### 坑 10：把「新种」的声明当成技术结论

ANI 低于 95% 通常被用来支持「这是一个新种」。但从数据分析到正式命名之间还有很长一段路：

- ANI 阈值是**惯例**，不是分类学的正式标准；
- 正式命名需要模式菌株、表型特征、以及在国际分类学委员会认可的平台（如 IJSEM）上的正式发表；
- GTDB 里的 `s__` 空缺或编号**不代表**「这是一个已认定的新种」，只代表 GTDB 的参考库里没有匹配的命名种。

规范写法：「该基因组与最近参考基因组的 ANI 为 92.1%，提示可能代表一个未描述的种（候选新种）」，而不是「这是一个新种」。

### 坑 11：把三套口径的结果拼在一张表里

一个常见但很难自查的错误：同一批样本，一部分用 GTDB-Tk 得到分类串，一部分用 fastANI 得到最近邻，一部分用 Mash 得到距离，然后把它们放进同一张「物种鉴定表」。

这三列的口径不同（体系不同、判据不同、单位不同），放在一起会制造一种「互相印证」的假象。正确做法是：

- 主口径选一套（通常是 GTDB-Tk 或 ANI），其余作为**独立的交叉验证**并在单独的表里给出；
- 交叉验证不一致时，报告分歧并解释原因（参考库覆盖、阈值、碎片化），而不是取其中之一。

### 坑 12：忽略「分类正确」与「基因组纯净」是两件事

一个被污染的基因组可以给出非常确定的分类结果。原因很简单：分类方法看的是标记基因的总体信号，而低比例的污染不会改变总体信号的方向。

所以流程里的顺序应当是：

```
读长层面筛查（有没有污染）→ 组装 → 质量与污染评估（CheckM2 / GUNC）
    → 分类注释（GTDB-Tk / ANI）
```

把分类放在质量评估之前，会让你在一个不可靠的输入上得到一个看起来很确定的结果，而这种结果最难被发现有问题。
