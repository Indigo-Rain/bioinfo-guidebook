# 第 4 章 组装质量与污染评估

## 4.1 这一层要回答什么问题

上一章产出了一份序列。这一层要回答的是：**这份序列能不能用来支撑我要下的结论？**

关键在于，这不是一个问题，而是六个互相独立的问题。把它们混在一起问，就会得到「我的基因组质量怎么样」这种无法回答的问题；拆开之后，每个问题都有明确的工具和明确的解释边界。

| # | 问题 | 工具 | 它**不能**回答什么 |
|---|---|---|---|
| 1 | 序列有多连续、有多大？ | `asmqc_quast` | 内容是否完整；是否被污染 |
| 2 | 基因内容齐不齐？ | `asmqc_busco` | 是否被污染；序列是否正确 |
| 3 | 必需基因是否完整、有没有多余标记？ | `asmqc_checkm2` | 近缘污染；局部序列错误 |
| 4 | 这些基因是否来自同一个谱系？ | `asmqc_gunc` | 近缘污染；基因组完整度 |
| 5 | 有没有局部的 indel 与被打断的 ORF？ | `asmqc_ideel` | 嵌合连接；污染 |
| 6 | 原始读长里混了什么？ | `qc_contamination_screen` | 组装产物的问题（它是上游的一步） |

### 这一层的真正用途是「设门槛并解释结论」，不是「打分」

初学者常把组装评估当成考试：拿到分数，高了就放心。这个心态会带来两个具体错误：

**错误一：把分数当成绝对质量。** 所有基因内容类指标都是**相对估计**。BUSCO 用一组「在近缘类群中几乎都是单拷贝」的基因去搜索组装，输出完整/碎片化/缺失的比例——它衡量的是「这组标记基因能不能在这个组装里被找到」。这既不能证明基因组完整（找不到的基因可能只是没拼出来），也不能证明基因组纯净（污染的序列可能恰好提供同源基因把分数补上去）。

**错误二：把门槛当成通用标准。** 「完整度 > 90%、污染度 < 5%」是 MAG（宏基因组组装基因组）场景的常用经验门槛，它来自 **CheckM1 时代**的实际需求：MAG 会被用来做「这个基因组有没有某条通路 / 某个基因」的推断，而这些推断的直接风险就是——**缺失的基因会被误读成「该基因组没有这个基因」**。90% 与 5% 是控制这种误读风险的经验取值，不是「基因组质量的定义」。

所以本章的核心判断是：

> **质量门槛是下游用途的函数。** 同一份基因组，用于物种鉴定可能完全合格，用于「这个菌能不能降解某底物」的结论可能完全不达标。门槛必须在项目开始时按用途设定，并写进方法。

## 4.2 输入、输出与中间文件长什么样

### 输入

| 类型 | catalog 类型 id | 说明 |
|---|---|---|
| 待评估的组装 | `contigs` / `genome-fasta` / `bins` | **必须是同一版本**（过滤后？抛光后？挂载后？见第 3 章坑 3） |
| 蛋白序列 | `protein-faa` | CheckM2 与 GUNC 的推荐输入；来源注释器会影响结果 |
| 参考基因组 | `reference-genome` | QUAST 的 `-r`；必须同物种且版本可追溯 |
| 参考注释 | `gff` | QUAST 的 `-g`；提供后才能统计基因区覆盖与部分错误类型 |
| 短读长证据 | `clean-reads` | IDEEL / assembly-scan 用；**必须与组装来自同一样本** |

### 输出

> 目录命名说明：本章沿用第 1 章的编号布局（`02_assembly`、`03_annotation`、`10_logs`），并为「基因组质量报告」单开 `04_qc`。第 1 章的通用布局把 `04` 留给定量矩阵（`04_quant`），那是转录组/丰度项目的用法；对单菌基因组项目而言 `04_qc` 更贴切。**关键是项目内保持一致**，并在 `samples.tsv` 或 README 里写明这套约定，而不是让读者去猜。

```
04_qc/
├── quast_sample/
│   ├── report.html        # 给人看
│   ├── report.tsv         # 给脚本看；跨样本汇总用这个
│   ├── icarus.html        # 仅在有参考时才有实际内容
│   └── transposed_report.tsv
├── busco_sample/
│   ├── short_summary.*.txt      # 一行式摘要，MultiQC 可直接读
│   └── run_*/full_table.tsv     # 逐基因结果：缺失基因列表比总分数更有信息量
├── checkm2/
│   └── quality_report.tsv       # 每个基因组一行：完整度、污染度、编码密度等
├── gunc_sample/
│   └── *.tsv                    # CSS（clade separation score）、污染比例、通过/不通过
├── ideel_sample/
│   └── errors.tsv               # 逐 contig 的可疑位点清单
└── multiqc/                     # 把上面全部汇总成一张热图（qc_multi_qc）
```

### 各输出的关键列与它们真正的含义

| 工具 | 关键字段 | 怎么读 |
|---|---|---|
| QUAST | `# contigs`、`Total length`、`N50`、`L50`、`GC (%)`、`N's per 100 kbp` | 都是**相对量**：依赖 `--min-contig` 阈值与序列版本；有参考时才有 `Genome fraction`、`misassemblies` |
| BUSCO | `C`（complete，含 `S` 单拷贝 / `D` 重复）、`F`（fragmented）、`M`（missing） | `D` 升高有两种完全不同的原因（污染，或真多拷贝/等位基因被分别拼出）；`M` 的**位置分布**比总数更有信息量 |
| CheckM2 | `Completeness`、`Contamination`、`Coding_Density`、`Total_Coding_Sequences` | 污染度是连续值（相比 CheckM1 的离散 bin）；与 CheckM1 数值**不可互换** |
| GUNC | `CSS`、污染比例、`pass`/`fail` 判定 | CSS 高**不等于**真污染：参考库未覆盖的新谱系、含大量水平转移/噬菌体/质粒的基因组都会被抬高 |
| IDEEL | 可疑位点坐标、contig、证据强度 | 清单里**包含真实生物学变异**；区分真伪要靠覆盖度与参考比较 |
| MultiQC | 汇总热图与阈值标红 | 它专门用来**发现离群样本**——单样本报告看不出批次效应 |

### 一个可执行的最小评估流程

```bash
S=sample; T=16; ASM=02_assembly/${S}.filtered.fasta

# 1) 连续性统计（无参考时只是统计；有参考才有 genome fraction 与 misassembly）
quast.py $ASM -o 04_qc/quast_${S} -t $T --min-contig 500

# 2) 基因内容完整度（谱系数据集必须与物种匹配，且项目内统一）
busco -i $ASM -m genome -l bacteria_odb10 -c $T \
      -o 04_qc/busco_${S} --offline

# 3) 必需基因完整度与污染度（推荐用蛋白输入，结果更稳定）
checkm2 predict --input 03_annotation/${S}.faa \
      --output-directory 04_qc/checkm2_${S} --threads $T

# 4) 跨类群嵌合检验（补上 CheckM2 的盲区）
gunc run -d $GUNC_DB -i 03_annotation/${S}.faa \
      -o 04_qc/gunc_${S} -t $T

# 5) 长读长/混合组装额外做一次局部错误核查
#    IDEEL 需要与组装同源的短读长证据
column -t 04_qc/ideel_${S}/errors.tsv | head -20

# 6) 汇总成项目级总览（把关键指标并排放，离群样本会自己跳出来）
multiqc 04_qc -o 04_qc/multiqc -n project_qc --force
```

注意第 1 步与第 3 步的输入来自不同阶段：QUAST 用核酸，CheckM2/GUNC 用蛋白。**蛋白来自哪个注释器会轻微改变 CheckM2 的结果**（Prokka、Prodigal、Bakta 得到的基因集合不同，同一基因组用不同注释结果跑 CheckM2 会有小数点级别的差异）。批次比较必须固定注释流程。

## 4.3 工具拼装思路（含选择决策树）

### 先确定你在评估什么对象

| 对象 | 质量含义 | 门槛的用途 |
|---|---|---|
| 单菌分离株草图 | 完整度用于确认「该拼的都拼出来了」；污染度用于排查实验室污染 | 通常不设硬门槛；不达标意味着要排查原因，而不是丢弃样本 |
| 单菌完成图 | 额外需要结构正确性证据 | 用于结构结论（复制子、共线性）前必须核对 |
| MAG（宏基因组 bin） | 完整度低是**常态**，代表「没拼出来」而不是「不存在」 | 门槛用于筛选可用于基因组层面推断的 MAG |
| 病毒 / 质粒序列 | 用专门的完整度分级（如 CheckV 的 Complete / High / Medium / Low / Not-determined） | 只有 Complete 与 High-quality 适合做基因组层面分析 |

**一个反复出现的概念陷阱**：MAG 与单菌草图的「完整度」含义不同。单菌样本里，完整度低通常意味着组装或数据有问题；MAG 里，完整度低几乎总是测序深度与群落复杂度的结果。因此把 MAG 的门槛套到单菌上、或把单菌的期望套到 MAG 上，都会得出错误结论。

### 决策树

```
你要评估的是什么？
├── 单菌组装（分离株）
│   ├── 只有短读长 / 长读长组装，下游是基因级结论（耐药、注释、分型）
│   │      → QUAST（统计）+ BUSCO（内容）+ CheckM2（必需基因 + 污染）
│   │         不达标时先排查：覆盖度不足？污染？过滤过度？
│   ├── 下游涉及染色体结构、质粒、共线性
│   │      → 上面三项 + 读长回贴覆盖度检查
│   │         长读长/混合组装再加 IDEEL 核查局部 indel
│   └── 是长读长或混合组装，且下游涉及编码区（移码、耐药点突变）
│          → 必做 IDEEL / assembly-scan
│             理由：同聚物区 indel 不会出现在 N50、BUSCO 或 CheckM2 里
└── MAG（宏基因组分箱产物）
    ├── 筛选可用于「基因组层面」推断的 MAG
    │      → CheckM2（完整度/污染度）+ GUNC（跨类群嵌合）
    │         注意：门槛来自 CheckM1 时代，用 CheckM2 时通过率会不同
    ├── 需要判断近缘污染（同种不同株混进同一个 bin）
    │      → CheckM2 与 GUNC 都不可靠
    │         要靠覆盖度异常、SNP 杂合位点、ANI 层面的分析
    └── 病毒 / 质粒序列
           → 专门的完整度/质量分级工具（如 CheckV；见第 6、8 章）

有没有近缘参考基因组？
├── 有，且同物种 → QUAST 加 -r（与 -g 参考注释）
│     可得到 genome fraction、misassemblies、indel 数
│     注意：参考越远，这些数字越差，且大量「misassembly」其实是真实种间差异
└── 没有 → QUAST 只是统计工具
      misassembly 与 genome fraction 缺失；Icarus 只能展示统计
      不要在没有参考的情况下声称做过“组装错误可视化”
      估计基因组大小要用 BUSCO/CheckM2 与 k-mer 估计，而不是把组装总长度当基因组大小

评估顺序有依赖吗？
└── 有，但依赖不复杂：
      先用长度过滤去掉碎片（asm_filter_contigs）→ 再评估
      先确认完整度/污染度 → 再解释分类学结果（第 5 章）
      先确认没有污染与嵌合 → 再做 Hi-C 挂载（否则错误会被固化）
```

### 为什么要同时看多套指标：三个真实场景

**场景 1：完整度很高，但 contig 数很多。**
这是**完全正常的草图状态**，不是失败。BUSCO 衡量基因内容，QUAST 衡量连续性，两者本来就独立。这类组装对基因级结论（注释、耐药、基因存在/缺失）完全够用，只是不适合结构结论。反过来，如果一份组装 contig 数很少但 BUSCO 缺失集中在同一个区域，那才是需要担心的信号——它指向一段真实的缺失区或一次组装断裂。

**场景 2：CheckM2 污染度 0%，但 GUNC 判定不通过。**
两者测的是不同的东西。CheckM2 判断「必需基因是否齐全、标记基因是否重复」，GUNC 判断「基因是否来自同一个谱系」。所以一份基因组可能标记基因很完整（CheckM2 满意），但含有一整段来自远缘类群的序列（GUNC 报警）。**两者一起看比单独看任一个都可靠**，这也是本层推荐「CheckM2 + GUNC」组合的原因。

**场景 3：所有指标都很好，但下游结果不对。**
最可能的原因是**近缘污染**（同种不同株混进来）与**局部序列错误**，这两类问题恰好落在所有指标的共同盲区：近缘污染让标记基因看起来就是「同一套」（CheckM2/GUNC 都不敏感）；同聚物区 indel 不影响连续性、甚至可能因为补偿性移码而让 BUSCO 完整度看起来不错。这就是为什么 IDEEL 与覆盖度检查是独立的、不能被替代的一步。

### 关于「验收标准」的写法

把 QUAST/BUSCO 的数字当验收标准之前，必须写清阈值的来源。一个可用的写法模板：

```
本项目以「用于基因存在/缺失与耐药筛查」为目的。
- 输入序列：02_assembly/<sample>.filtered.fasta（--min-contig 500，见 10_logs/*.filter_stats.tsv）
- 连续性：contig N50 > 20 kb（QUAST 5.x, --min-contig 500）
- 基因内容：BUSCO bacteria_odb10 完整度 > 98%，duplicated < 2%
- 必需基因：CheckM2 完整度 > 90%，污染度 < 5%（工具与数据库版本见日志）
- 嵌合：GUNC 判定 pass（数据库版本见日志）
- 未通过的处理：记录原因，按用途降级使用（例如不用于基因组层面的推断）
```

没有这段文字，同一张表由不同人解读会得出不同结论。

## 4.4 关键参数取舍

### QUAST

| 参数 | 默认 | 建议与理由 |
|---|---|---|
| `--min-contig` | 500 | **所有统计量的基础阈值**。改成 0、200 或 1000 会明显改变 contig 数与 N50。跨项目比较 N50 前必须先统一这个值——这是本章最重要的一条可比性要求 |
| `-r / --reference` | 无 | 提供后才有 genome fraction 与 misassembly 统计；参考必须同物种且版本可追溯 |
| `-g / --features` | 无 | 提供参考注释（GFF）才能统计基因区覆盖与部分错误类型 |
| `--est-ref-size` | 无 | 无参考时用估计的基因组大小计算 genome fraction，**只作粗略参考，不能当作结论** |
| `-t` | 以版本为准 | Icarus 与 HTML 生成在单线程下会明显拖慢 |
| `--fragmented` / `--large` | 关闭 | 针对高度碎片化或大型基因组的处理模式；含义与限制以官方文档为准 |
| `--space-efficient` | 关闭 | 更省内存，但部分可视化所需信息会受限（以官方文档为准） |

**一个必须记住的解释规则**：总长度大于预期基因组大小**不等于**组装得好。可能是污染、重复区被分别组装多次，或杂合区域被拆开。要结合 duplication ratio、CheckM2/BUSCO 与分类结果一起判断。

### BUSCO

| 参数 | 默认 | 建议与理由 |
|---|---|---|
| `-m` | 以版本为准 | `genome` / `proteins` / `transcriptome` 三种模式。核酸模式要跑基因预测，结果对预测器版本敏感——**有注释时优先用 `proteins`**，更快也更稳定 |
| `-l` | 以版本为准 | 谱系数据集。越专一灵敏度越高（`enterobacterales_odb10` 比 `bacteria_odb10` 更贴合），但只能用于对应类群；**换数据集后分数不可直接比较** |
| `--auto-lineage-prok` | 关闭 | 自动为细菌/古菌挑选谱系；需要本地已有 odb 数据，运行时间显著增加 |
| `-c` | 以版本为准 | CPU 数；同时影响基因预测与同源搜索阶段 |
| `--offline` | 关闭 | **生产环境建议开启**，避免不同时间跑到不同版本的数据集 |
| `-f` | 关闭 | 覆盖已有输出目录；重复运行不加它会直接报错 |

### CheckM2

| 参数 | 默认 | 建议与理由 |
|---|---|---|
| `--input` | 必填 | 单个文件或整个目录 |
| `--extension` | 以官方文档为准 | 批量目录时的后缀过滤。`.fa` / `.fasta` / `.fna` 混放时容易**静默漏文件**，建议项目内统一后缀 |
| `--database_path` | 自动查找 | 离线环境必须显式给出，否则运行时会尝试下载 |
| `--threads` | 以版本为准 | DIAMOND 搜索阶段是主要耗时 |
| 质量门槛（非工具参数） | 完整度 > 90 且污染度 < 5 | MAG 场景的常见经验值；**具体项目应结合下游用途设定并写明依据** |

### GUNC

| 参数 | 默认 | 建议与理由 |
|---|---|---|
| `-d / --db` | 必填 | 预下载的参考数据库路径；**数据库版本决定判定结果，必须记录** |
| `-i / --input_dir` | 二选一 | 单个蛋白文件或整个目录 |
| `--file_suffix` | 以官方文档为准 | 批量模式下的后缀匹配；后缀不一致会**静默漏样本** |
| `-t` | 以版本为准 | DIAMOND 搜索是瓶颈 |
| 判定阈值 | 以官方文档为准 | 不同阈值会明显改变通过率；跨项目比较必须统一并写明 |

### IDEEL / assembly-scan

| 参数 | 建议与理由 |
|---|---|
| 短读长比对质量与碱基质量阈值 | 决定判定证据强度；阈值越松报出的可疑位点越多，人工核查成本越高（具体参数以官方文档为准） |
| 最小覆盖度 | 低覆盖区域的判定不可靠；清单必须结合覆盖度一起解读 |
| 组装与读长的同一性 | **必须一致**。短读长来自另一样本时，所有真实差异都会被报成「错误」 |
| assembly-scan 的输入 | 组装 FASTA；适合在送去做注释或提交之前先做一次整体体检 |

### 读长层面的污染筛查（`qc_contamination_screen`，属于第 2 章但本章要用它的结果）

| 参数 | 默认 | 建议与理由 |
|---|---|---|
| `--db` | 无 | Kraken 索引库；必须记录用的是标准库还是 plusPF 还是自定义库及其日期，**不同库结果不可比** |
| `--confidence` | 0.0 | 筛查杂音多时提到 0.1–0.5，会显著减少假阳性但增加 unclassified |
| `--minimum-hit-groups` | 2 | 至少几个独立 k-mer 命中组才算分类；控制假阳性的实用参数 |
| `--use-names` | 关闭 | 报告里显示物种名而非仅 taxonomy id；人工阅读必须加 |

**关键判断是阈值而不是有无。** 任何分类器都会给出少量误分类读长，几个百分点以下的杂音通常可以忽略；但如果某个非目标物种**稳定占用 10% 以上**，就必须查清原因——可能是真污染，也可能是数据库里缺少目标物种的近缘基因组导致读长被就近分配。

## 4.5 常见坑

这一节讲**跨步骤的系统性问题**，而不是单个工具的参数细节。

### 坑 1：把「门槛」当成「质量的定义」

「完整度 > 90%、污染度 < 5%」的来历需要说清楚：它出自 MAG 场景（MIMAG 标准与 CheckM1 时代的实践），目的是控制「缺失基因被误读为不存在」的风险。

由此推出的三条实用结论：

1. **门槛是用途的函数。** 用于物种鉴定时，完整度 85% 的基因组可能完全够用；用于「该菌能否利用某底物」的通路完整性推断时，同一个基因组不够。
2. **门槛与工具绑定。** CheckM2 与 CheckM1 的模型与训练集不同，同一份基因组的数值会有系统性偏差；用 CheckM1 时代定下的经验阈值去卡 CheckM2 结果，会得到不同的通过率。方法学里必须写明工具、版本与数据库版本。
3. **通过/不通过是二值化，而质量是连续谱。** 把连续指标压成二值判定会丢掉重要信息：完整度 89% 与 45% 都写「不通过」，但它们能支撑的结论完全不同。规范做法是给出具体数值与用途判断，而不是只写「达标/未达标」。

### 坑 2：BUSCO 与 CheckM2 的「完整度」不可互换

两个工具都输出一个叫「完整度」的数字，但它们：

- 用不同的基因集（BUSCO 用单拷贝直系同源标记基因；CheckM2 用机器学习模型结合编码特征与标记基因信息）；
- 用不同的算法（同源搜索 vs 机器学习回归）；
- 对污染的定义与敏感度完全不同（BUSCO 通过 `duplicated` 间接提示，CheckM2 直接给污染度）。

**同一份基因组在两个工具下的数值会有系统性差异。** 所以：

> 报告里写「完整度 X%」时必须同时写工具与版本。用一个工具定的门槛去卡另一个工具的结果，是最常见的隐性错误。

还有一层更微妙的问题需要说清楚：**用细菌单拷贝基因集评估细菌基因组，本身带有循环论证的成分。** 标记基因集是从已知的细菌基因组里挑出来的，所以「完整度 99%」的准确表述是「这组已知的细菌标记基因几乎都能在这个组装里被找到」，而不是「这是一个完整的基因组」。它能可靠地发现**缺基因**（这是一个真实且有价值的信号），但不能**证明**基因组完整——如果你的基因组有一段区域所有参考基因组里都没有对应物，这段区域的完整性永远不会被这些指标检验到。

### 坑 3：污染度接近 0 不等于没有污染

CheckM2 对**近缘污染**几乎不敏感：同种不同株、或同一属内高度相似的第二个菌株混进来时，它们的标记基因看起来就是「同一套」，污染度不会升高。GUNC 在这一类问题上同样无能为力——它检验的是「是否来自同一个大类群」。

近缘污染要靠另外三类证据发现：

1. **覆盖度异常**：把读长回贴，看是否有一段区域的覆盖度是染色体平均值的约 2 倍（两个菌株的共有区域）或 1.5 倍（部分共有）。这是最直接的信号。
2. **SNP 杂合位点**：单菌样本在特定位点出现稳定的双等位信号（各占约 50%），强烈提示两个近缘菌株混合。
3. **ANI 层面的分析**：把组装的不同区域分别与参考比较，看是否落在不同的 ANI 水平上。

一个相关的推论：**近缘污染也会让「基因存在/缺失」矩阵出现诡异的模式**——两个本应高度相似的菌株之间出现大量互补的差异。第 7 章会展开这一点。

### 坑 4：MAG 的 rRNA 条件被机械套用

MIMAG 对「高质量 MAG」的定义包含 rRNA 基因的存在条件，但**短读长宏基因组几乎检不到 rRNA**（rRNA 区在组装与分箱中都容易被丢掉）。机械套用这个条件会误杀绝大多数实际上可用的 MAG。

正确的做法是：把 rRNA 条件理解为「如果检到了，说明组装质量高」，而不是「没检到就不合格」。同时记住另一条更重要的前提：**MAG 是草图，缺失的基因不能解释为「该基因组没有这个基因」，只能说明「本次组装没拼出来」。** 基于 MAG 的基因存在/缺失结论必须带上这一前提。

### 坑 5：把 `duplicated` 升高直接当成污染

BUSCO 的 `duplicated` 升高有两种完全不同的原因：

1. **污染**（另一份近缘基因组混入）；
2. **真实的重复**：组装把两个等位基因分别拼出（杂合区域被拆开），或该基因在该谱系中确实是多拷贝。

区分方式：结合 GC、覆盖度与分类证据。如果 `duplicated` 升高同时伴随覆盖度双峰或 GC 偏离，才更可能是污染；如果两个拷贝的序列高度相似且覆盖度各占约一半，更可能是等位基因被分开组装。

### 坑 6：混淆「完整度」与「连续性」，进而做出错误决策

| 观察到的情况 | 正确的解释 | 不该做的事 |
|---|---|---|
| BUSCO 完整度高，contig 数很多 | 基因内容齐全，结构碎片化——**正常草图** | 不要因此重做组装或补测序 |
| BUSCO 完整度低，contig 数很少 | 可能缺失真实内容，或谱系选错，或参考模型覆盖不足 | 不要只靠重新组装来解决；先看缺失基因列表 |
| contig 数很少，但覆盖度在某处断裂 | 可能的错误连接或污染区 | 不要直接用于下游注释与提交 |
| 总长度远大于预期，完整度也很高 | 污染、重复区多次组装，或杂合区被拆开 | 不要当成「组装得很全」 |

**一个高价值的实践**：看 BUSCO 的**缺失基因列表**而不是总分数。如果大量缺失基因集中在同一个区域或同一功能类别，往往指向真实的缺失区或一次组装断裂，而不是随机噪声。总分数是 97% 还是 98% 通常不重要，缺失在哪里才重要。

### 坑 7：N50 的可比性陷阱（这一层最常见的报告错误）

QUAST 默认只统计不短于 500 bp 的 contig。把 `--min-contig` 改成 0 或 1000，会得到**明显不同的 N50 与 contig 数**。因此：

- 跨工具、跨论文比较 N50 前，必须先确认：阈值、用的是 contig 还是 scaffold、是否做过长度过滤。
- `scaffolds.fasta` 里的 N 会让 N50 变好、最长序列变长，**但不代表信息更多**。用 scaffolds 报统计、用 contigs 做注释，再把两者混着引用，是这一层最常见的自相矛盾。
- 把「过滤后的 N50」和「过滤前的总长度」放进同一张表，同样是错误的——统计量必须来自同一份序列，并且注明是哪一版。

### 坑 8：把「无参考」当成「无错误」

没有近缘参考时，QUAST 只是统计工具：`misassembly` 与 `genome fraction` 缺失，Icarus 只能展示统计。此时**不能**声称做过「组装错误可视化」。

反过来，有参考时也要小心：`misassembly` 与 `genome fraction` 只在提供参考时才有意义，而且**参考越远这些数字越差**——用一个近缘但不同种的参考，会产出大量其实是真实种间差异的「misassembly」。没有同种参考时应明确说明这些指标缺失，而不是拿一个远缘参考的数字下结论。

### 坑 9：局部序列错误躲过了所有常规指标

一份 BUSCO 99%、N50 数百 kb 的长读长组装完全可以有几十个同聚物区 indel。这类错误：

- 不影响连续性（contig 长度不变）；
- 不一定降低 BUSCO 完整度（可能只是让一个基因带上移码）；
- 完全不影响 CheckM2 与 GUNC（它们看的是基因内容与谱系来源）。

但它会直接影响：基因注释的边界与基因数、耐药点突变的判读、移码导致的假假基因。所以：

> **只要下游涉及编码区的结论，长读长/混合组装就必须做一次局部错误核查**（`asmqc_ideel`）。这是常规指标覆盖不到的盲区，不是可选的加分项。

同样要记住 IDEEL 的输出**包含真实生物学变异**：如果短读长来自另一株菌，真实的 indel 会被一并列出；判断真伪要看证据强度，以及位置是否落在组装图的重复区或低覆盖区。而且它是**诊断而非修正**工具——发现问题后的处理顺序是：先确认是否为真实变异，再决定重新抛光还是回到组装步骤。

### 坑 10：版本与数据库被当成「附注信息」

这一层的结果对数据库版本极其敏感：

- BUSCO 换谱系数据集或换大版本 → 分数不可比；
- CheckM2 换数据库 → 数值变化；
- GUNC 换数据库 → 通过/不通过判定变化；
- Kraken 换库 → 物种占比变化（而它是本章关于「有没有污染」的第一手证据）。

因此记录规范是：

```
工具名 + 版本 | 数据库/数据集名 + 版本 + 下载日期
输入序列 md5 | 阈值与判定规则 | 实际命令
```

只记软件版本不足以复现任何一个注释或分类结果——**数据库版本的权重常高于软件版本**。

### 坑 11：用质量筛选悄悄引入选择偏倚

在 MAG 场景里，「按完整度 > 90%、污染度 < 5% 筛选」是一个非常自然的动作。但它同时做了一件不显眼的事：**它把低完整度的 MAG 从下游分析中移除了，而「能否拼出高质量 MAG」本身与物种的丰度、基因组大小、群落复杂度相关。** 结果是：

- 「该群落中存在哪些物种」的结论会偏向高丰度、易组装的类群；
- 「哪些基因在群落中更常见」的统计会系统性地偏向那些恰好被拼出来的基因组；
- 不同样本之间的 MAG 数量差异会被当成生物学差异，而它可能只是测序深度的差异。

可操作的应对：**报告未通过筛选的 MAG 数量与它们的完整度分布**，让读者知道被排除掉的是什么；在跨样本比较时，用统一的门槛并说明每样本的通过率。筛选本身没有问题，不报告筛选过程才是问题。

### 坑 12：把所有检验都留到最后

质量与污染评估最贵的那一部分不是运行工具，而是**发现问题时已经走得太远**。一个成本排序：

| 发现时机 | 典型代价 |
|---|---|
| 读长层面（`qc_contamination_screen`，第 2 章） | 几分钟，只需重新选样本或重新建库 |
| 组装刚完成（本章） | 一次重新组装 |
| 注释之后 | 重新组装 + 重新注释 |
| 泛基因组 / 比较分析之后 | 整条链路重跑，且可能已经写过一版结论 |
| Hi-C 挂载之后 | 上游错误被固化到染色体级别，很难回溯 |

所以本章的检验不是流程末尾的「质检盖章」，而是**在每一步下游动作之前的前置条件**。第 5 章会给出一个具体的依赖关系：完整度/污染度不达标的基因组不要急着做分类学鉴定，因为分类结果可能不可靠。

## 4.6 与面板模块 id 的对应

| 模块 id | 一句话说明 |
|---|---|
| `asmqc_quast` | 组装统计与（有参考时）错误检验的标准报告；N50 依赖 `--min-contig`，跨项目不可比 |
| `asmqc_busco` | 用单拷贝直系同源基因评估基因内容完整度；能发现缺基因，但不能证明基因组完整 |
| `asmqc_checkm2` | 机器学习式的完整度与污染度估计；数值与 CheckM1 不可互换，对近缘污染不敏感 |
| `asmqc_gunc` | 检测跨类群的嵌合与污染，补上 CheckM2 的盲区；需要蛋白输入与独立数据库 |
| `asmqc_ideel` | 用短读长证据找出长读长组装中的 indel 与被打断的 ORF；诊断而非修正 |
| `qc_contamination_screen` | 读长层面的污染筛查；它是成本最低、发现最早的一道检验 |
| `asm_filter_contigs` | 过滤后必须重跑评估，否则指标与序列版本不一致 |
| `qc_multi_qc` | 把各工具的指标汇总成项目级热图；它的真正用途是发现离群样本 |
| `py_pandas_io` | 读入质量报告做阈值筛选与汇总表；检查矩阵形状是固定自检 |
| `viz_ggplot2` | 画完整度-污染度散点图，离群基因组一眼可见 |
| `wf_reproducibility` | 工具、数据库版本、阈值与校验和的记录规范 |
| `meta_bin_refine` | MAG 场景下用本层的质量报告做分箱优化与去冗余的依据 |
| `meta_assembly_qc` | 宏基因组组装质量的完整流程（含去冗余）；与单菌评估的口径不同 |
| `meta_mag_taxonomy` | 本层的质量结论是解释 MAG 分类注释的前提 |
