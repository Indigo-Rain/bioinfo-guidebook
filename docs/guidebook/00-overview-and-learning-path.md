# 第 0 章 总览与学习路径

## 0.1 这套知识系统是什么

微生物生物信息学的一个特点是：**几乎没有哪一步分析是「一个软件」完成的**。你真正在做的事情，是把十几个到几十个工具用 Python 与 shell 拼起来：

```
原始读长 → 质控 → 组装 → 注释 → 比较 → 统计 → 图
   fastp    SPAdes  Bakta  Panaroo  pandas  ggplot2
```

这种「模块化拼接」的形态带来一个具体问题：**工具之间的接口（数据格式与约定）比工具本身更容易出错**。一个 GFF 到 BED 的坐标转换写错，不会报错，只会让下游所有区间偏移一个碱基；一个样本名的大小写不一致，会让合并在不报错的情况下丢掉一半样本。

因此这套系统由两部分组成，它们解决的是同一个问题的两面：

| 部分 | 位置 | 解决什么 |
|---|---|---|
| **交互式面板** | [`index.html`](../../index.html) | 把「用哪些模块、按什么顺序、数据怎么流」画清楚，并实时提示接口是否对得上 |
| **Markdown 指南** | `docs/guidebook/*.md` | 讲清每一步的方法学取舍、参数理由与常见坑 |

两者**由同一份数据派生**：`data/modules/*.json` 是唯一数据源，面板中的模块、说明、参数与坑都来自它。这意味着文档与面板不会脱节——改了数据，重新构建，两边一起更新。

## 0.2 怎么用面板

打开 [`index.html`](../../index.html)（双击即可，**无需联网、无需安装任何东西**）。面板分三栏：

**左栏**——模块库与预设。可以按关键词搜索（支持中文与工具名，如 `fastp`、`组装`、`binning`），也可以直接用「预设流程」。

**中栏**——画布。三种搭法：

1. 从左侧把模块**拖进**画布，从节点右侧圆点拖到另一个节点即建立连线
2. **双击**左栏模块，它会直接放到画布中央
3. 打开「预设流程」载入一条完整的端到端流程，再按需增删

**右栏**——检查器。点击画布上的模块，这里显示它的完整说明、输入输出端口、参数取舍、常见坑，以及典型上下游。

### 连线颜色的含义（这是面板最有用的部分）

面板对每条连线做三档判定，判定依据是**数据类型**而不是名字：

| 颜色 | 含义 | 该怎么办 |
|---|---|---|
| 🟢 绿色实线 | 上下游类型完全一致 | 可以直接连 |
| 🟡 黄色虚线 | 有一方是「任意」类型，或只是同类数据换了个名字 | 需要你确认格式是否真的对得上 |
| 🔴 红色点线 | 类型不匹配（跨了数据结构） | 必须中间插一个做格式转换的模块 |

红色线**不会被阻止**——面板允许你连上去并把它标红，同时在「校验」标签里给出可插入的候选模块。这是刻意的设计：分析流程有时确实需要非常规的转换，工具不应该替你做决定，但必须让问题可见。

## 0.4 四个方向的心智模型

不同方向的「核心难点」其实不是同一类问题。认清这一点能帮你判断时间和精力的分配。

**① 微生物基因组学**——难点在**组装与注释的边界**
基因组小（几 Mbp）、可完成图，但重复区（rRNA 操纵子、IS 元件、噬菌体）会让短读长组装碎成几十个 contig。真正的判断点是「这个基因组的完成度够不够回答我的问题」——比较基因组需要高完成度，而只做物种鉴定时草图就够了。

**② 宏基因组 / 微生物组**——难点在**统计而不是工具**
工具链是成熟的（Kraken2、MetaPhlAn、HUMAnN、MEGAHIT、MetaBAT2），但结果几乎总会「有显著差异」。原因是这类数据有三个叠加的陷阱：**组成性**（相对丰度总和恒为 1，一个物种上升必然导致其它下降）、**测序深度差异**（低深度会系统性低估丰富度）、以及**样本量普遍偏小**（几十个样本要做上百次比较）。本指南把统计陷阱集中写在第 8 章的 pitfalls 与模块的 pitfalls 里，因为它们比任何参数都更能决定结论真假。

**③ 转录组**——难点在**rRNA 去除与重复数**
细菌 mRNA 没有 poly(A) 尾，不能用真核常见的 oligo-dT 富集；而 rRNA 常占 90% 以上。这一步的效果直接决定后面有没有信号。另一半是实验设计：每组 3 个生物学重复是**底线**，n=2 时任何差异表达结论都不可靠。

**④ 系统发育与进化**——难点在**模型与支持度的解释**
建树软件的操作门槛很低（一条命令出树），但「这棵树能不能用来下结论」取决于三件事：替换模型是否合适、比对是否可靠、以及**支持度到底证明了什么**。高 bootstrap 只说明「给定这份比对与这个模型，这个拓扑是稳定的」，它**不能**排除长枝吸引、组成偏倚这类系统误差。

## 0.5 三个必须早期建立的工程习惯

这三件事在本指南里反复出现，因为它们决定了分析是「做过一次」还是「可重复」。

**① 目录结构先定好。** 所有步骤把产物写到约定的目录，不写进项目根目录，也不写到临时位置。推荐布局：

```
project/
├── 00_raw/         # 原始数据，只读，永不修改
├── 01_clean/       # 质控后
├── 02_assembly/    # 组装
├── 03_annotation/  # 注释
├── 09_results/     # 最终结果与图
├── 10_logs/        # 日志、质控报告、溯源清单
├── refs/           # 参考数据库与索引（体积大，单独管理版本）
└── envs/           # 环境定义与锁文件
```

`00_raw` 只读这条纪律的价值在排查问题时才体现：任何结果的差异都可以回溯到某一步而不是「数据被人改过」。

**② 每一步都落盘，并检查产物非空。**
一个只存在于内存里的中间结果等于不可复现。同时注意断点判据要用「文件存在**且非空**」——被中断的任务常留下 0 字节文件，只判断存在会让下游拿到空数据并产生位置远离真正原因的错误。

**③ 记录版本，而且别忘了数据库。**
```
软件版本 + 数据库版本 + 输入校验和 + 实际命令
```
这四项齐了结果才可追溯。**数据库版本的权重常高于软件版本**：同一版 Kraken2 配不同的库会给出不同的物种组成，同一版 GTDB-Tk 配不同版的 GTDB 会给出不同的分类。只记软件版本不足以复现任何一个注释或分类结果。

## 0.6 关于面板的技术说明

面板是**离线自包含**的单个 HTML 文件：没有任何外部依赖（无 CDN、无外部字体、无网络请求）。你可以把它拷到任何机器上双击打开，也可以和项目一起归档。

- 你拼的流程保存在本机浏览器的 localStorage 里，**不会离开这台机器**
- 可以导出三种格式：管线 JSON（便于再次导入）、Bash 脚本、Python 脚本
- 导出的脚本是**结构骨架 + 参数起点**，不是可直接投产的脚本。流程存在类型错误时，脚本头部会把它们列成注释清单

关于面板的定位需要说清楚：它**不运行任何分析**，也不替代任何工具文档。它负责把结构画对、把接口问题暴露出来、并把结构变成可编辑的代码起点。
