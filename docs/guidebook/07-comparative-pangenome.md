# 第 7 章 比较基因组与泛基因组

## 7.1 这一层要回答什么问题

「比较」不是一个问题，而是四类问题，它们的方法、输入与结论强度都不同：

| # | 问题 | 典型方法 | 输入规模 | 输出 |
|---|---|---|---|---|
| 1 | 这两个基因组到底哪里不同？ | 共线性比较（`comp_syri`） | 2 个（少数几个） | 倒位 / 易位 / 特有区区块表 |
| 2 | 这一组基因组共有什么、各自特有什么？ | 泛基因组（`pange_panaroo` / `pange_roary`）、直系同源群（`pange_orthofinder`） | 几个到上千个 | 家族存在/缺失矩阵、核心/附属分区、累积曲线 |
| 3 | 这些菌株之间有多远？是不是同一次暴发？ | SNP 距离（`comp_snp_dist`）、cgMLST（`var_typing_cgmlst`）、MLST（`var_mlst`） | 几十到几千 | 距离矩阵、聚类分组 |
| 4 | 哪些基因与某个表型相关？ | 存在/缺失矩阵 + 系统发育感知的关联方法 | 需要表型数据 | 关联基因清单 |

### 这一层最重要的结构性判断：比较分析有三个前提

任何跨基因组比较的结论，都建立在三个前提上。缺任何一个，结论就不可比——而且**这三类问题都不会报错**。

**前提一：上游同源（assemblies 与 annotations 必须走同一条流程）。**
混用不同注释器（Prokka、Bakta、NCBI 已提交的 GFF）时，基因边界与命名策略不同，同一个基因可能被切成两段或合并成一段，凭空造出大量**假家族**。表现为附属基因组虚高、核心基因组偏低。同样的道理适用于组装流程（不同组装器、不同过滤阈值、不同测序平台）。

**前提二：亲缘距离可比。**
泛基因组的输入应当是**同一物种**的一组基因组。跨物种的泛基因组没有意义——同源关系会混入直系同源与旁系同源，家族数与核心基因组数字都失去解释。下游比较之前先用 ANI 确认（第 5 章）。

**前提三：采样范围明确，并且写进结论。**
这是最容易被忽略、后果却最严重的一条：

> **泛基因组是否「开放」、核心基因组有多大、某个基因是否「附属」，全都取决于你采了哪些基因组。**

同一克隆复合体的几十个暴发株系放在一起，泛基因组必然看起来「闭合」；换成覆盖全物种多样度的样本，曲线会继续上升，核心基因集会缩小。所以这一类结论必须与采样策略一起写，否则读者无法判断它的适用范围。

### 这一层最容易混淆的一点：「树」有四种口径

本层会产出或消费四种树，它们的假设不同、能回答的问题不同、冲突时的解释也不同：

| 树 | 输入 | 反映什么信号 | 什么时候用它 | 主要局限 |
|---|---|---|---|---|
| **核心基因串联树**（core-SNP 树） | 核心基因的单拷贝比对串联（`pange_core_align`） | 核心基因组的垂直遗传信号 | 同种菌株的系统发育与分型 | 丢掉附属基因信号；重组频繁的物种必须先剔除重组区 |
| **SNP 距离树**（成对距离聚类） | 共有核心位点上的两两差异数（`comp_snp_dist`） | 相对参考坐标系下的碱基差异 | 暴发调查、传播聚类 | 依赖参考选择与掩蔽策略；阈值必须物种特异 |
| **泛基因组树** | 家族存在/缺失的 0/1 矩阵 | **基因内容**的相似性 | 展示「基因内容的聚类」；与 SNP 树对照 | 它不是系统发育树：没有替换模型，也没有共同祖先的假设 |
| **单拷贝直系同源树**（OrthoFinder 的物种树） | 每个 orthogroup 的基因树汇总 | 跨属/跨门的直系同源关系 | 跨物种、跨属的比较 | 它是**推断出来的工作树**；正式发表前应用串联核心基因比对重新建树并比较拓扑 |

这四种树**冲突是正常现象**，而且冲突本身常常是有价值的生物学信息（不完全谱系分选、重组、水平转移）。规范做法是：报告冲突、给出解释方向，而不是「选一棵好看的」。

### 四种树与四种距离，不要互相换算

与树类似，距离也有四种口径，它们之间没有换算关系：

| 距离 | 单位 | 分辨率上限 | 典型用途 |
|---|---|---|---|
| ANI | 百分比一致性 | 种级（≥95%） | 是不是同一个种 |
| cgMLST | 等位基因差异数 | 接近 core-SNP，且编号可跨实验室共享 | 分子监测、暴发识别 |
| core-SNP | 碱基差异数 | 单碱基 | 近缘菌株的传播推断 |
| 泛基因组家族差异 | 家族数（或 Jaccard） | 基因内容层面 | 基因内容比较，而非亲缘关系 |

把「Mash 距离 0.01」「ANI 99.5%」「差 12 个 SNP」写在同一张表里当一致性证据，是这一层最常见的口径错误。

## 7.2 输入、输出与中间文件长什么样

### 输入

| 类型 | catalog 类型 id | 说明 |
|---|---|---|
| 各基因组注释（GFF3） | `gff` | 泛基因组构建的输入；**必须来自统一的注释流程** |
| 各基因组蛋白序列 | `protein-faa` | OrthoFinder 的输入；文件名即物种名 |
| 基因组序列 | `genome-fasta` | SyRI 的输入；也是注释工具需要配套提供的序列 |
| 多菌株核心变异位点 | `vcf` | SNP 距离的输入之一 |
| 核心 SNP 串联比对 | `alignment-fasta` | SNP 距离或建树的输入 |
| 掩蔽区间表 | `tsv-table` | 重复区、rRNA 操纵子、前噬菌体、低比对质量区 |
| 表型与元数据 | `tsv-table` | 关联分析的必需输入 |

### 输出

> 目录命名说明：比较与泛基因组的产物不属于第 1 章通用布局里的任何一类（既不是注释、也不是定量矩阵），因此本章为它单独使用 `07_comparative`。**关键是同一个项目内不要出现两套并行的比较结果目录**——`pange_*`、`comp_*`、`phy_*` 的产物混在一起时，最容易发生的事就是下游脚本读到了另一个工具的同名文件（见 7.5 坑 9）。

### 各输出的关键字段与读法

| 输出 | 关键字段 | 怎么读 |
|---|---|---|
| Panaroo / Roary `gene_presence_absence.csv` | 家族行 × 基因组列（值为空或基因名）、`annotation` 等注释列 | **注释列不是基因组**：把注释列当成一个「基因组」统计会得到每个家族「存在率 100%」的荒谬结果。矩阵形状自检（列数 = 基因组数 + 注释列）应作为固定步骤 |
| `summary_statistics.txt` | 核心家族数、附属家族数、总计 | 核心家族数应落在该属的常见区间；明显偏低先查注释一致性与污染 |
| OrthoFinder `Orthogroups_GeneCount.tsv` | 每个 orthogroup 在各物种中的拷贝数 | 含**拷贝数信息**；下游建树前必须显式过滤「每基因组恰好一个拷贝」 |
| `*.syri.out` | 第 8 列（差异类型）与坐标 | 若 `NOTAL`（两侧都无法比对）占比异常高，优先怀疑比对质量或基因组不完整，而不是真有那么多特有区 |
| 累积曲线数据 | 家族数 vs 基因组数、均值与标准差 | 曲线**依赖基因组的加入顺序**；单次顺序的结果不可靠 |
| SNP 距离矩阵 | 两两差异数 | 必须在**同一批共有位点**上计算；报告时至少要给出核心位点数与掩蔽策略 |
| RF 距离矩阵 | 拓扑距离 | 类群数多时对大树「不敏感」；比较前必须对齐类群集合 |

### 一个可执行的分析流程（同种菌株的泛基因组 + 核心树）

```bash
S=escherichia; T=16

# 0) 前提检查：所有基因组必须已经统一注释（同一工具、同一版本、同一参数）
#    并用 CheckM2/GUNC 确认没有污染（第 4 章）
ls 03_annotation/pan/*.gff > 07_comparative/gff_list.txt
wc -l 07_comparative/gff_list.txt        # 与预期基因组数核对

# 1) 泛基因组构建（显式指定清理模式；推荐先看结果规模）
panaroo -i 03_annotation/pan/*.gff -o 07_comparative/panaroo \
        --clean-mode strict -t $T
head -20 07_comparative/panaroo/summary_statistics.txt

# 2) 家族分区与累积曲线（固定随机种子与置换次数）
#    在 R 中用 micropan：见 7.4 的用法骨架

# 3) 核心基因比对 → 修剪 → 建树
mafft --auto --thread 4 07_comparative/panaroo/core_gene_alignment.aln \
    > 07_comparative/core/core_concat.aln.fasta
trimal -in 07_comparative/core/core_concat.aln.fasta \
       -out 07_comparative/core/core_trim.aln.fasta -automated1
iqtree2 -s 07_comparative/core/core_trim.aln.fasta -m MFP \
        -B 1000 -alrt 1000 -T $T --prefix 07_comparative/core/iqtree_run

# 4) 修剪与不修剪各建一次树，比较拓扑是否一致（第 7.5 坑 6）
iqtree2 -s 07_comparative/core/core_concat.aln.fasta -m MFP \
        -B 1000 -T $T --prefix 07_comparative/core/iqtree_notrim

# 5) 需要 SNP 距离时（暴发调查）
snp-sites -c -o 07_comparative/core/core_snp.aln.fasta \
          07_comparative/core/core_concat.aln.fasta
snp-dists -c 07_comparative/core/core_snp.aln.fasta \
    > 07_comparative/snp.dist.tsv

# 6) 拓扑比较（修剪 vs 不修剪）
#    在 R 中用 phangorn 计算归一化 RF 距离矩阵
```

## 7.3 工具拼装思路（含选择决策树）

### 决策树 A：结构层面的比较（两个基因组）

```
几个基因组？
├── 2 个（或少数几个）→ 共线性比较（SyRI / nucmer）
│   ├── 先确认亲缘距离：ANI ≥ 90%（更高更稳）
│   │     低于约 90% 时比对会碎片化，NOTAL 区域暴增，
│   │     此时报出的"重排"多半是比对失败的产物而不是真实重排
│   ├── 近缘（≈99% ANI）→ minimap2 -ax asm5 生成比对
│   ├── 稍远或需要精确坐标 → nucmer（--maxmatch 的选择必须写进方法）
│   └── 关键：参考基因组是谁必须标注
│         以 A 为参考报出的倒位，换成以 B 为参考后坐标与方向都会变
└── 很多个 → 不要做两两全套比较
      要么做"参考 × 所有菌株"的成对比较并汇总，
      要么先用共线性聚类挑选代表性基因组
```

一个必须先做的检查：**草图的 contig 断点会被记成重排。** 比较之前先确认两个基因组的 contig 数与完整度，否则「大量易位」很可能只是没拼通的假象。这一条与第 3 章的坑 1 是同一件事的两个方向：组装质量是比较结论的天花板。

### 决策树 B：基因内容层面的比较（泛基因组）

```
比较的对象是什么？
├── 同一物种的几十到几百个株系，目标是核心基因组与附属基因
│      → Panaroo（推荐）或 Roary（经典）
│         核心差异：**是否做比对校正**
│           Panaroo 会对每个簇做多序列比对，把明显放错簇的序列
│           （移码、碎片、注释边界偏差、污染序列、被拆成两段的同一基因）
│           挑出来重新分配
│           Roary 完全依赖注释给出的边界与 BLAST 相似度，不做校正
│         判据：
│           - 输入注释质量参差（混用注释器、含碎片化或污染基因组）→ Panaroo
│           - 复现旧结果、与既有数据集对齐 → Roary（并说明未做比对校正）
│         注意：**两者结果会不同，家族数不能混在同一张表里引用**
├── 跨属、跨门，或需要显式处理旁系同源与拷贝数
│      → OrthoFinder
│         输入是蛋白组（一个基因组一个 FASTA）；输出 orthogroups、基因计数矩阵、
│         单拷贝直系同源群列表与一棵有根物种树
│         注意：它**不会**替你把单拷贝直系同源基因挑出来、比对、串成建树矩阵；
│               那一步仍要接 pange_core_align
├── 只需要一张 0/1 存在缺失矩阵（来源可能是耐药基因库、标志基因集）
│      → comp_gene_presence
│         构建时必须显式定义四件事（见 7.4）：什么算一个"基因"、
│         家族一致性阈值、旁系同源如何表示、家族注释取哪条代表序列
└── 想回答"这个基因与某个表型相关"
       → 在存在/缺失矩阵之上做**系统发育感知**的关联分析
          普通卡方 / Fisher 检验会把谱系差异报成表型关联
```

**Panaroo vs Roary 的取舍，用一句话概括：**

> 如果输入注释质量整齐、且能与既有数据集对齐，Roary 够用；只要输入里有任何一个基因组来自不同注释流程、或者含有污染与碎片，就必须用 Panaroo 的比对校正，否则假家族会静默抬高附属基因集。

### 决策树 C：距离与分型

```
要回答"有多远"还是"是不是同一株"？
├── "是不是同一个种" → ANI（第 5 章），不属于本章
├── "是不是同一株 / 是不是同一次暴发"
│   ├── 物种是克隆性的（低重组，如结核分枝杆菌、炭疽芽孢杆菌）
│   │      → core-SNP 距离（snp-dists / Snippy 核心流程）
│   │         必须先掩蔽重复区、rRNA 操纵子、前噬菌体
│   ├── 物种重组频繁（如肺炎链球菌、脑膜炎奈瑟菌）
│   │      → 先做重组剔除（Gubbins / ClonalFrameML），或改用 cgMLST 的等位基因差异
│   │         一个导入片段能一次带来几十个 SNP，直接用 SNP 距离会被重组主导
│   └── 需要与跨实验室的监测数据对接
│          → cgMLST（离散的等位基因编号，可共享）
│             注意：cgMLST 的编号只在**同一 schema 版本**内有效
└── 只需要粗略的流行病学标签（ST 型别）
       → MLST：跨年代、跨地区长期监测有用，但**分辨率不足以做暴发调查**
          同一个 ST 内的菌株可以有几十到几千个 SNP

关于阈值：
├── "≤ 5 个 SNP 属于同一传播链"之类的数字来自**特定病原体与特定暴发场景**
│     不是通用法则；引用时必须给出处、并说明人群与时间跨度
└── 阈值附近的菌株归属不稳定
      掩蔽策略或位点集微调就能让 4 SNP 与 6 SNP 的菌株互换阵营，
      关键传播链必须做敏感性分析，而不是只报一个结果
```

### 决策树 D：核心基因比对与建树

```
核心基因集怎么定义？
├── 100% 共有（严格核心）→ 最保守、几乎没有缺失
├── 95% 出现率（软核心）→ 能多纳入数百个基因，代价是引入缺失数据
│     缺失数据会让含缺失的分支支持度被系统性压低，甚至把真实分群拆散
└── 无论选哪个：**出现率阈值必须与结果一起报告**

核酸还是氨基酸？
├── 株系层面（同一物种）→ 按密码子对齐的**核酸**矩阵
│     蛋白比对信息量更高但株系水平分辨力不足
│     必须用回译（back-translation），不能直接把氨基酸比对当核酸用
└── 属以上层面 → 蛋白比对（或用密码子模型）

要不要去重组？
├── 克隆性物种 → 可以不剔
└── 重组频繁的物种 → **必须先剔除重组区**
      否则高 bootstrap 支持的是重组历史而非垂直遗传

要不要修剪？
└── **修剪与不修剪各建一次树**，比较拓扑
     修剪通常提高支持度，但也可能丢掉真实信息；
     两者冲突时重点看冲突分支是否落在高 gap 区
     注意：**core SNP 比对不该用 trimAl**（见 7.5 坑 10）

用哪个建树工具？
├── 需要严格结论、要报告支持度 → IQ-TREE（-m MFP + -B + -alrt）或 RAxML-NG
├── 序列数上千到上万、只要拓扑全貌 → FastTree
│     注意：默认输出的**不是 bootstrap**，而是局部支持值，数值系统性偏高
└── 建议：用两个 ML 实现（IQ-TREE 与 RAxML-NG）各建一次，作为
      "换工具是否改变结论"的稳健性检查——这是审稿人最容易提出的问题之一
```

### 四种树的详细对照（冲突时怎么解释）

| 冲突 | 可能原因 | 怎么查 |
|---|---|---|
| 核心基因树 vs SNP 树 | 位点集不同（核心基因 vs 共有位点）、掩蔽策略不同 | 对齐位点集重算；报告两者 |
| 核心基因树 vs 单基因树 | **不完全谱系分选（ILS）** 或重组 | 比较多个独立基因的树；统计冲突分支的比例 |
| 泛基因组树 vs 任何系统发育树 | 泛基因组树反映**基因内容**相似性，不是共同祖先 | 这是口径差异，不是矛盾；两者应分别报告 |
| OrthoFinder 物种树 vs 串联核心基因树 | 旁系同源处理、缺失数据、基因树汇总方式不同 | 检查单拷贝群数量与缺失率，而不是直接选一棵 |
| 换工具后拓扑变了 | 搜索启发式、模型参数化差异 | 用 RF 距离量化；若只影响短内部枝，说明数据本身分辨力不足 |

### 决策树 E：关联分析（哪些基因与表型相关）

```
有表型数据、有存在/缺失矩阵
└── 必须先处理**系统发育混杂**
      0/1 矩阵带有极强的系统发育信号：亲缘相近的菌株天然共享基因
      直接用卡方 / Fisher 检验找"与致病性相关的基因"，
      得到的往往是谱系差异而不是致病机制
    规范做法：
      - 用把树作为协变量纳入的方法（如 Scoary、treeWAS、
        系统发育广义线性模型一类）
      - 在报告中说明所用树与校正方式
      - 报告多重检验校正
    另一条必须记住的边界：
      **附属基因数与基因组数量强相关**，不能直接拿"附属基因更多"
      推断菌株致病性更强；要比较应在相同基因组数下稀释取样
```

## 7.4 关键参数取舍

### Panaroo

| 参数 | 默认 | 建议与理由 |
|---|---|---|
| `--clean-mode` | 以官方文档为准 | `strict` 最激进地清理可疑注释，`moderate` 折中，`retain` 保留全部。**注释质量参差时用 `strict`**，重注释过的同源数据可用 `moderate` |
| `-a / --alignment` | core | 选择输出核心基因比对还是全基因组比对；只做核心 SNP 树时用 `core` 可省时间与磁盘 |

| `--merge_paralogs` | 关闭 | 把高度相似的旁系同源家族合并；**会明显减少家族总数，必须在报告里说明是否开启** |
| `-t / --threads` | 1 | 默认值在批量任务里非常慢，务必按机器核数显式设置 |
| 阈值参数（家族一致性 / 长度差异） | 以官方文档为准 | 默认值随版本调整过；**正式分析应在报告中写出实际使用的阈值**，否则结果无法复现 |

一个实操细节：Prokka 的 GFF 自带 `##FASTA` 段，而只输出坐标表的注释工具没有序列；后者必须把基因组 FASTA 一起传给 `-i`，否则提取不到基因序列，**报错信息往往与真正原因相隔很远**。

### Roary

| 参数 | 默认 | 建议与理由 |
|---|---|---|
| `-i` | 95 | BLASTP 最小一致性百分比；下调会合并更多家族，核心基因数随之上升。**必须与旧结果保持一致才能比较** |
| `-cd` | 99 | CD-HIT 去冗余的一致性阈值；与 `-i` 的搭配决定家族边界，**两个都要写进报告** |
| `-e` | 1e-5 | BLASTP 的 E 值上限；放松会引入更多远缘匹配 |

| `-g` | 关闭 | 不拆分旁系同源；默认会拆分。**研究问题涉及拷贝数时必须显式记录是否用了 `-g`** |

| 参数 | 默认 | 建议与理由 |

## 7.5 常见坑

这一节讲**跨步骤的系统性问题**。

### 坑 1：上游不同源，是一切假差异的总源头

这是本章最重要的一条，它有两个层次：

**组装层面**：不同批次用了不同的组装器、不同的过滤阈值、不同的测序平台，会让同一位点能否被跨越不同、截断基因的比例不同。这些差异**不会报错，也没有明显的统计信号**，只会在结果里表现为「某些菌株的附属基因特别多」。

**注释层面**：混用 Prokka、Bakta 与 NCBI 提交的 GFF，会让同一个基因被切成两段或合并成一段，凭空造出大量假家族，表现为附属基因组虚高、核心基因组偏低，**而且不会报任何错**。

一个非常显眼的诊断信号：矩阵里出现**一对「互补缺失」的假家族**（两个家族的存在/缺失模式完全相反）。出现这种模式时，先怀疑注释不一致，而不是先解释生物学意义。

另外一条与前提三相关的坑：**未做污染筛查的草图基因组会把质粒、接头甚至宿主序列带进泛基因组**，直接污染附属基因集。入组前先做完整度与污染评估（CheckM2 / GUNC），并把结果一并记录。

### 坑 2：「核心基因组大小」是阈值的产物，不是生物学常数

核心与附属的划分完全由阈值决定：

- Panaroo / Roary 的家族一致性阈值、长度差异容忍度、是否合并旁系同源；
- 核心基因的出现率阈值（100% 还是 95%）；
- 核心/软核心/shell/cloud 的百分比边界。

换一组阈值，核心家族数变化上百个是常见的。所以：

> 「核心基因组大小」这个数字离开阈值与版本号没有意义。跨论文比较前先对齐定义。

同样地，**Panaroo 与 Roary 给出不同结果是预期的，不是 bug**：Panaroo 会做比对校正、合并被拆开的基因、清理低置信注释，因此家族数通常更少、核心基因更稳定。**两个工具的数字不能混在同一张表里引用**，它们之间也没有换算关系。OrthoFinder 同理——一个基于蛋白相似度与 MCL，一个基于图聚类加比对校正，同一批基因组上家族数差几百到上千完全正常。

### 坑 3：泛基因组曲线的形状由采样决定，不由物种决定

「泛基因组是否开放」是靠累积曲线是否饱和来判断的。但曲线有三重依赖：

1. **依赖样本多样性。** 同一克隆复合体的暴发株系放在一起，泛基因组必然看起来「闭合」。要回答物种层面的问题，样本必须覆盖该物种的多样度，否则结论只在采样范围内成立。
2. **依赖基因组的加入顺序。** 单次顺序的结果不可靠，应多次随机顺序取平均值并展示分散度（`n.perm ≥ 100`，固定随机种子）。
3. **依赖矩阵本身的质量。** 注释不统一或被拆分的基因会同时抬高 cloud 家族数并压低 core 家族数；先确认核心家族数落在该物种的常见区间，再谈曲线拟合。

还有一条常见的过度解读：**曲线仍在明显上升时，说明「加入更多基因组还会带来新基因」，此时「核心基因」的估计不稳定，不应作为最终结论。** 「还需要测多少基因组」不能靠目测曲线——要么给出拟合参数（如 Heap 定律 `n = κ·N^γ`）与外推区间，要么明确写「未饱和，不做外推」。

### 坑 4：系统发育混杂是关联分析最大的坑

0/1 存在/缺失矩阵带有极强的系统发育信号：亲缘相近的菌株天然共享基因。直接用卡方 / Fisher 检验找「与致病性相关的基因」，得到的往往是**谱系差异而不是致病机制**。

规范做法：用系统发育感知的方法（Scoary、treeWAS、系统发育广义线性模型一类）把树作为协变量纳入，并在报告中说明所用树与校正方式。如果确实没有树可用，至少要在报告中明确写出「未做系统发育校正」这一局限，而不是把它当成一个小问题。

与此相关的另一条：**附属基因数与基因组数量强相关。** 不能直接拿「附属基因更多」推断菌株致病性更强；要做这类比较，应在相同基因组数下稀释取样，或使用系统发育校正的关联方法。

### 坑 5：重组会一次引入成串 SNP

重组对本章的三种分析都有影响：

- **SNP 距离**：一个导入片段能一次带来几十个 SNP，直接把无关菌株拉近或把相关菌株推远。对重组频繁的物种，不做去重组就说「差 30 个 SNP 所以不是同一暴发」是站不住的。
- **核心基因树**：重组频繁的物种必须先剔除重组区，否则**高 bootstrap 支持的是重组历史而非垂直遗传**。
- **核心基因的判定**：重组会让某些基因在部分菌株中「看起来是附属的」。

正确的处理顺序是：先判断物种的重组水平（文献 + 初步结果），再决定是否做重组剔除、或改用 cgMLST 的等位基因差异。

### 坑 6：支持度高不等于结论正确

这一条适用于本章产出的所有树。bootstrap / UFBoot / SH-aLRT / TBE 都只反映「当前数据与当前模型下的稳定性」，**无法发现系统误差**。以下情况都会给出高支持度的错误分支：

- **长枝吸引**：快速进化谱系被错误地聚在一起；
- **组成异质性**：不同类群的 GC 或氨基酸组成差异被模型当成系统发育信号；
- **替换饱和**：远缘类群间同一位点反复替换，信号已被抹平；
- **模型错误**：该用 `+R` 却用 `+G`、该分区却单分区；
- **比对错误**：同源关系判断错误；
- **不完全谱系分选（ILS）与重组**：单个基因树的信号与物种树不一致。

识别它们要靠别的手段：改变类群采样（去掉可疑的长枝看拓扑是否改变）、换模型或加位点异质模型、比较多个独立基因的树、用拓扑检验比较备择拓扑——**而不是把 bootstrap 重复数从 1000 提到 10000。**

另外三条与支持度直接相关的具体坑：

- **不同来源的支持度不能混在一棵树里解读。** SH-aLRT、UFBoot、标准 bootstrap、FastTree 的局部支持值数值分布完全不同，不能相互换算，也不能套用同一组阈值。
- **FastTree 默认输出的不是 bootstrap。** 它是局部支持值，系统性偏高；写成「bootstrap = 0.95」是方法学错误。
- **树必须与比对配套。** 用修剪前的比对去评估修剪后建的树，重采样得到的支持度没有意义。

### 坑 7：RF 距离的局限，以及比较前必须做的事

RF 距离是本章量化「两棵树差多少」的标准工具，但它有三个必须知道的限制：

1. **对大树「不敏感」。** 类群数很多时大量浅层分支共享，即使生物学上差异很大，归一化后的 RF 也可能很小；需要时改用加权 RF 或 TBE 这类度量。
2. **没有显著性。** 距离大不等于差异显著，距离小也不等于结论一致；要判断冲突是否被数据支持，必须做拓扑检验（SH、AU 等）并给出 p 值。
3. **类群集合必须先对齐。** 任何一棵树多了或少了类群，RF 距离就失去意义；比较前先取交集并重新剪枝，**而不是让工具按名字自动丢弃**。

还有一条解释上的要求：把多棵树放在一起算 RF 距离矩阵并聚类之后，要看「结果是聚成**方法簇**还是**生物学簇**」——这两种结果的含义完全不同。如果拓扑主要按方法聚类，说明结论对方法敏感，需要谨慎；如果按类群或基因聚类，则说明数据本身存在冲突。

### 坑 8：草图上的「大量重排」多半是假的

草图的 contig 断点会被 SyRI 之类的工具记成重排。在比较之前先确认两个基因组的 contig 数与完整度，否则「大量易位」很可能只是没拼通的假象。

另外两条相关的具体问题：

- **重复序列会让比对在多个位置之间摇摆**，直接产生假倒位或漏掉真倒位（rRNA 操纵子、IS 元件、噬菌体区尤其明显）；含大量可移动元件的菌株要人工核对几个关键区块。
- **SyRI 需要同一坐标体系的比对文件**：把 nucmer 的 delta 与 coords 混用、或把不同参数两次比对的输出拼在一起，会得到看似正常但内部矛盾的区块表。

### 坑 9：同名文件与同名概念

两个具体陷阱：

**同名文件**：Roary 与 Panaroo 输出**同名文件**（`gene_presence_absence.csv`、`core_gene_alignment.aln`）但内容不同。放在同一个结果目录里极易被下游脚本误用。**按工具分目录存放，并在路径里带上工具名。**

**同名概念**：「核心基因组」在三个地方含义不同——泛基因组工具说的核心家族、核心基因出现率阈值定义的核心集、core-SNP 比对里的核心位点。写方法时要说清用的是哪一个。

### 坑 10：core SNP 比对不该用 trimAl

这类「比对」是人为拼接的**等长 SNP 列**，几乎没有 gap，修剪的统计假设不成立：对它做 `-gappyout` 通常什么也不删，做 `-strict` 则可能删掉真实信号。

同理，**把氨基酸比对当作核酸矩阵**是最常见的静默错误之一：密码子错位后统计出的「SNP」数量与位置都是错的。株系水平建树必须按密码子回译成核酸。

### 坑 11：「SNP 距离小」不等于「有传播关系」

传播判断必须结合流行病学信息（时间、地点、病房），且需要知道该物种的自然突变速率作为背景——**不同物种的阈值完全不同。**

两个具体做法问题：

- **最常见的错误是把每个菌株「与参考基因组的 SNP 数」当成菌株间距离。** 这比较的是各菌株与参考的关系，不是彼此的关系，聚出来的「传播链」没有意义。
- **测序质量差的菌株会人为抬高距离**：低覆盖度、混菌样本或未去除的污染读长都会带来假 SNP。先把质量指标（覆盖度、比对率、杂合位点比例）查一遍再解释距离。

### 坑 12：伪重复与样本独立性

**同一受试者的多次分离株在树上是伪重复。** 把它们当作独立样本会低估多样性，也会人为放大克隆群的证据强度。这在医院暴发调查里非常常见（同一个病人多个时间点、多个部位分离株）。

处理方式：在分析前明确每个「样本」的定义（一个病人一株？还是全部保留？），并在方法里说明；做统计检验时把病人作为随机效应或聚类单位。

### 坑 13：用从头组装算的距离与用读长比对参考算的距离不是一回事

前者包含组装错误与基因内容差异，数值会明显偏大；两者**不能混在同一张表里**。同理，用不同参考、不同掩蔽策略、不同位点集得到的距离矩阵也不能混用。

一条更细但常被忽略的要求：**距离必须在同一批共有位点上计算。** 把每个菌株各自「与参考的差异数」拿来互相比较，比较的其实是各自与参考的关系。

### 坑 14：把「树」当成分析的终点

一棵漂亮的树很容易让人以为分析结束了，但树只回答「谁和谁更近」。本章的四个问题里，树只服务于第 3 个；第 1、2、4 个问题分别需要区块表、家族矩阵与关联分析。

反过来的错误也存在：把泛基因组树当作系统发育树来讨论分化顺序。**泛基因组树反映的是基因内容相似性，它没有替换模型，也没有共同祖先的假设**，不能用来谈「谁更古老」。

### 坑 15：只做核心树，丢掉附属基因的信号

核心基因树反映的是核心基因的一致信号。耐药基因、毒力岛、可移动元件的进化信息都在**附属基因**上，只做核心树会看不见。如果研究问题涉及这些，需要另做 accessory 分析（存在/缺失矩阵、附属基因树、关联分析）。

这也是「四种树」这一节的实际意义：**没有一棵树能回答所有问题**，选哪棵取决于问题。
